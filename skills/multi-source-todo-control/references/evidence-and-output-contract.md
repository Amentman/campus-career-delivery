# 证据与输出合同

只读检查默认使用已有快照，不自动刷新／解密。报告必须列出微信解析／缓存截止时间和新鲜度缺口；缓存未覆盖任务时间窗或截止不明时，相关来源不能称最新或全量。已有明确刷新授权可在最小范围执行并核对结果，无需重复确认。

仅在执行“多源待办总控”时读取本文件。

## 证据字段

每条待办使用以下字段：

| 字段 | 合同 |
|---|---|
| 学生 | 正式姓名或稳定匿名 ID；身份不唯一时写 `Open` |
| 事项 | 动词开头，只写一个下一动作 |
| 责任人 | 用户、明确接单者或正在等待的对象 |
| 时间 | 硬时间／承诺截止／建议检查点／`Open` |
| 状态 | 用户待处理／已承诺未交付／已委派盯结果／等待回复／受阻／完成／冲突待核实 |
| 证据 | 来源类型、会话或对象、原始证据时间、一句事实摘要 |
| 完成标准 | 能从真实来源回读到的关闭事实 |
| 事实等级 | `Confirmed`／`Externally verified`／`Inferred`／`Knowledge supplement`／`Open` |

事实等级约束：

- `Confirmed`：当前可读的用户、学生或协作方原话，或真实交付物。
- `Externally verified`：当前可核验的 JD、公司、日历等外部事实；不能变成学生经历。
- `Inferred`：从多条证据推导但尚未直接确认，只能用于排序或提出核实动作。
- `Knowledge supplement`：岗位或方法知识，只能解释为什么值得核实。
- `Open`：身份、语义、时间、责任或状态仍不确定。

## 覆盖矩阵字段

按学生逐行记录：

| 学生 | 服务主表 | 学生群 | 学生私聊 | 协作聊天 | 规划／索引 | 交付记录 | 缺口与最小动作 |
|---|---|---|---|---|---|---|---|

每个格子写 `覆盖状态 + 最近检查到的证据时间`，例如：`已覆盖｜10-06 13:40`、`部分覆盖｜仅见11:00语音`、`未检查｜本轮无检索证据`、`读取失败｜索引错误`。不要在格子里塞完整聊天摘要。

判定顺序：

1. 本轮没有实际检索证据：`未检查`。
2. 已检索但没有唯一会话匹配：`无匹配会话`。
3. 已定位会话但工具失败：`读取失败`。
4. 只读到部分正文、触点或不完整时间窗：`部分覆盖`。
5. 正文和约定时间窗均完成检查：`已覆盖`。

用户说“没有后续交付证据”只能支持对应事项尚未被证明完成；除非同时说明已检查交付记录，否则不能把“交付记录”格写成已覆盖或部分覆盖。

覆盖率按“可检查格子”计算：

```text
已覆盖率 = 已覆盖格子数 / （应检查格子数 - 不适用格子数）
```

部分覆盖、未检查、无匹配会话和读取失败都不能计入已覆盖。学生身份未知的来源不并入分母，另报 `未知来源 N 个`，直到完成身份匹配。

## 优先级与归属

按以下顺序比较：硬时间或逾期、用户对外承诺、无人承接的学生请求、是否阻塞他人、风险损失、完成成本。

- 学生群新请求无人实质回复：默认用户本人；下一步为回复或明确分配。
- 私聊中用户已经明确接单：合并群聊请求，不再制造第二条“回复学生”，核心动作改为交付承诺物。
- 协作方明确接单：责任人写协作方，用户动作写检查结果；没有明确动作和接手意图的“收到／我看看”不算接单。
- 已发材料但需要对方反馈：进入等待回复；发送本身不等于完成。
- 服务主表与新聊天冲突：保持主表状态，把冲突写成核实和人工回填动作。
- 语音、图片或附件正文不可读：只能确认触点，不能猜测请求内容。

## 作品集判断表

| 证据组合 | 作品集需要 | 规划状态 | 输出位置 |
|---|---|---|---|
| 学生明确求助，且用户已承诺给方向；没有可回读规划 | 已确认需要 | 未规划或待交付 | 已确认需要且未规划 |
| 规划页写明方向，但没有启动／产出证据 | 已确认需要 | 已规划待启动 | 常规待办或等待，不进入“未规划” |
| 仅服务表项目栏空白 | 暂无证据 | Open | 待核实候选 |
| 目标岗位通常会看作品集，但无学生／JD／服务策略证据 | 可能需要 | Open | 待核实候选，并标 `Knowledge supplement` |
| 已有可回读代码、文档或页面，但验收不完整 | 已确认需要 | 进行中 | 常规待办，写明缺失验收 |

### 示例

服务主表中甲同学作品集字段空白；群聊里甲明确问“我没有作品集怎么办”，用户私聊承诺“明天给方向”，但没有规划页或交付证据。正确结果是一条待办：`给甲交付作品集方向`，责任人为用户，承诺截止为次日，完成标准是甲实际收到可执行方向；作品集判断写“已确认需要／未规划或待交付”。不要再生成重复的“回复甲”，也不要把结论归因于空白字段。

## 写入模式的额外门槛

只有用户明确要求更新某个对象时才进入写入模式。写前列出“会改／只读／不碰”，锁定唯一学生和字段白名单；写后回读修订号、目标字段、公式、未授权字段和变更数量。任何一处未回读都必须标为未验收，不能用 CLI success 或 revision 增加代替完整验收。
