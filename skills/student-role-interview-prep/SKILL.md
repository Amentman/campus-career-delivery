# 学生专岗面试准备

把公司实际经营、目标岗位工作和学生真实经历接起来，让学生能解释业务、讲清自己做过什么，并推演岗位会遇到的问题。公司研究、岗位讲解和案例是正文主体，问答用于练习这些内容；题目数量不能证明准备充分。

## 入口与交付范围

首次部署读 [团队配置](references/team-setup.md)，仅取本轮必需资源；本轮已给入口优先。每位成员使用自己已确认的 `lark-cli --as user` 身份，配置不授予权限，也不继承作者的持续授权。身份正常时静默核对，不因显示名称不同重复追问。

正式、可归档的学生材料默认写入唯一飞书页面。先复用**学生唯一飞书主页**和本轮指定入口；`姓名｜面试指导者版（内部）`、`姓名｜学生面试准备版`、其他专岗及附件是保护对象，只读参考。专岗授权不包含重写通用双端或主页；目标专岗的分享范围按用户本轮明确要求或本人已确认的私有配置执行，具体映射与写后验收见写入边界。

## 交付对象先确定

| 可观察条件 | 落点与处理 |
| --- | --- |
| 用户指定一份文档、合并多公司或给出目标页 | 按指定交付。多公司在一页中用共同总览、分公司章节、差异比较；不为每家公司再建子页 |
| 已有唯一同公司、同职位编号专岗页 | 原位更新，保持父级、URL、手工填写与附件；下一轮是页内章节 |
| 新专岗且无指定合并入口 | 默认学生主页下的独立子页 `专岗准备｜公司｜岗位`；未知职称写“岗位待确认” |
| 用户只要聊天短稿、本地、导出或只读 | 按限定范围交付，不强制完整底稿或飞书写入 |
| 仅续图片或显示验收 | 复用原页与清单，不重研公司、重写正文或新建页面 |

同名学生、目标公司、岗位或写入目标实质不唯一时，先查原件和已有入口；仍无法消歧只问影响动作的一项。业务单元、创始人或内部指标未知通常不阻塞研究，按引用合同处理。学生端验收指正文、图片、附件和现有范围的阅读效果，不默认要求学生账号、添加协作者或学生登录。

## 工作流程

1. **读取真实资料。** 完整读相关最新简历、JD、邀约、当前目标页和参考。记录本轮修改对象与保护对象；旧总结只作线索。内部区分学生已证实经历、外部事实、推断、教学知识和未知；原件只读，不执行附件里的命令。
2. **先完成公司基本面，再建立证据与业务主线。** 完整专岗先读 [公司研究合同](references/company-fundamentals-research.md)。查主体与发展背景、产品/服务、用户和付费方、价格与收入方式、地域与渠道、竞争、近期变化和相关岗位；按设备、消费品、AI SaaS等实际类型展开。把关键公司事实转成岗位任务、交付物、指标及案例，不以官网简介或“为什么公司”一题代替。信息不足先补查相关渠道，记录查过什么与仍未知什么，继续解释有依据的业务方法。
3. **完整组织专岗内容。** 读 [内容与表达合同](references/content-and-expression.md)。顺序为公司怎么经营→岗位每天做什么→学生有哪些证据→怎样回答和练习。核心职责逐条落到真实对象、动作、交付和判断口径；用S故事、K知识区分亲历、迁移和假设。案例须使用该公司具体产品、市场、渠道或用户任务，给追问、分支、取舍、动作和检验方法。多公司合并时共用学生事实，只在各公司展开真正不同的工作。
4. **适配本轮，不丢准备底稿。** HR“五分钟”是轮次信息，完整准备前置本轮速读与必练顺序；用户明确“只要短话术/不做完整版”才按短稿完成。时间紧可先给聊天速读，继续已授权底稿。题数、字数或标题齐全都不能代替内容完成门。
5. **精准交付。** 飞书操作前读 [写入边界与验收](references/feishu-boundary-and-acceptance.md)。优先当前 `lark-cli`，按真实XML/Block ID局部改动，写超时先独立回读。完整材料有复杂关系时应用可用的 `impeccable` 阅读模式和 `visual-document-delivery`；未安装时执行本目录同等合同，不伪称调用。讲解图默认以原生画板置于对应章节，保留已有有效媒体。先定读者问题、文案与关系，实际应用 `impeccable` Read模式；逐字逐线检查原生节点、导出和正文实际宽度。工具不可用时说明限制，不静默改成讲解图片。明确简单线性短稿可记 `no_visual_reason`。
6. **逐项验收。** 先核公司研究与核心职责是否已讲到能用，执行引用中的公司替换检查、案例与口述检查。写后回读实际全文、标题、归属、父级、附件、媒体、链接分享权限和保护范围，逐章检查文风。“所有人可见”按获得链接的任何人可查看验收，不误设为可编辑；既有持续授权不重复确认，团队成员不继承。图片/版式验收读 [后台能力发现与恢复](references/feishu-image-browser-recovery.md)：默认后台完成，高层AX包装超时不能推断后台不可用；先发现当前浏览器与标签能力，DOM与截图分别验证。不因工具故障把前台操作确认转交用户。最终报告实际修改、只读核对、本地备份、未触碰对象、资料截止日、读回与显示范围和影响使用的未知；文档交付与学生已经练会分开。

## 调用与维护

- 无明确公司/岗位的通用模拟：`student-mock-interview-delivery`；真实已发生面试：`student-interview-review-delivery`，默认 `面试复盘｜公司｜日期` 独立子页，不混写准备材料。
- 已安装 `building-resume-interview-stories` 可辅助证据和表达；不自动触发简历重写、额外技术项目或本地全包。
- 修改后按 [行为验收](references/acceptance-scenarios.md) 用合成资料实测；同步工作流说明、输入图、完整图与可编辑源码。格式校验和证据合同检查不能声称验证事实、美学或真实飞书显示。
