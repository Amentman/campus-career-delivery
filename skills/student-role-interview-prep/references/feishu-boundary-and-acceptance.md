# 飞书写入边界与验收

## 统一页面与视觉合同

- 用户指定一份文档、合并多家公司或既有目标页时优先执行；同页用总览、分公司章节和差异比较，不额外为各公司建页。无指定时专岗页的默认父级是学生唯一飞书主页，标题为 `专岗准备｜公司｜岗位`；通用老师版与学生版保持独立，不能被专岗页覆盖。若已有同岗页，原地复用并保持父级。
- 飞书专岗页中的流程、架构、Case判断、时间线与关系图默认用原生画板置于对应章节；证据比较适合原生表格时不重复画图。保留已有有效媒体；链接、附件和源码不能代替正文可见画板，写后核对原生节点、导出和实际阅读宽度。用户明确限定的简单线性短稿可以纯文字，并在 `visual_contract` 记录具体 `no_visual_reason`。

## 本人名下交付与可见性边界

- 默认使用已确认的用户本人账号，交付在用户本人名下的既定学生目录／本轮已确认父级；已有唯一页面原地复用。本人登录身份、创建者／所有者和父级静默读取核对，不重复询问账号归属。
- “学生版”“学生端可见性／可读性”默认验收学生版正文、图片、附件、阅读路径及现有分享范围；不等同于要求识别学生飞书账号、把学生加入协作者或切换学生账号登录。名单未显示学生姓名不构成交付失败，不把缺少学生昵称、注册手机／邮箱列为必填信息或阻塞。
- 用户说“写在我下面／放在我名下就行”时，按本人归属与已确认目录继续交付，保留现有权限；不再追问学生账号，不发送邀请或通知，不扩大分享。
- 用户明确要求给某个学生账号开权限、发送给该账号，或验证该账号能否访问时，才处理该具体账号与最小必要权限；优先读取已有信息，确有身份歧义才问与该授权直接相关的问题。只有本人身份、写入目标或已授权操作存在具体异常时，才暂停对应写入；图片与正文验收照常按授权推进。

## 先定位，再写入

优先使用 lark-cli。有当前版本的 `lark-shared`、`lark-wiki`、`lark-doc` 指南时读取；上传附件时再读可用的 `lark-drive` 及媒体指南。未安装这些辅助文件时先查 CLI 相应域和具体子命令 `--help`、实际只读返回，不能猜参数或伪称已读指南。

1. 找到唯一学生主页及已存在的通用学生版／老师版，确认真实标题和父子关系；缺少通用双端不自动创建，也不阻塞已明确主页下的专岗准备。用户给出的入口优先；无入口时搜索已有知识库。列表有分页就继续到候选范围完整，不把第一页当全部。
2. 优先检查用户指定入口及既有专岗页，再检查学生主页和通用学生版下的候选子页，按公司、岗位和职位编号核对，不能只凭一个模糊词匹配。唯一同岗页原地复用且不迁移父级；无匹配时按用户已指定父级或当前项目规则新建，校招默认学生主页下；多个可能匹配时只问一个必要问题。
3. 本轮状态中记录通用学生版、老师版与要更新的专岗页的完整 XML、revision_id、章节顺序、附件／媒体标识及手工内容，作为比较依据。原页没有修改授权时保持只读，发现旧规范问题也不能顺手修复。无需持久落盘复制简历或建立学生备份目录。

## 正式写入

- 用户指定／既有唯一页优先。新页无指定时服从当前项目规则，校招默认路径为 `学生主页 → 专岗准备｜公司｜岗位（编号，如有）`；记录本轮已确认的父级。命名服从用户已明确约定。
- 用户指定合并时只写已确认的合并文档；未指定合并时新岗位准备写进新子页。同岗更新只操作该页目标章节。默认不更改上级正文，不以导航、便利、首屏可见为由插入内容。已有复盘与其他岗位页保持原位。
- 专岗页开头保留原始简历附件或可访问的现有简历来源入口；提供真实 JD 来源、准备日期和返回通用学生版链接。JD 截图可按需要直接上传；HR 聊天只提取面试必要信息，不复制无关联系人资料。
- 正文原生标题唯一，不重复 H1；按内容拆段，短表用于映射，示范稿用连贯口语段落。长文逐章写入并局部回读，追加时确认目标位置，避免章节倒序。
- 更新前记录版本；保护专岗页既有有效内容、附件和学生手工填写。写失败先读回判定是否已成功，不能盲目重试产生重复页、重复内容，也不能新建替代页掩盖失败。
- 默认不改权限、所有权，不对外发送，不将内部审计放进学生页面；具体账号访问任务仅按上节明确授权处理。用户要求仅创建 Skill 时只修改本地技能文件，不能顺便重做任何学生的飞书材料。

## 独立回读验收

写入后实际读取，而不是仅检查成功回执：

1. **位置与唯一性：** 新页 parent_node_token 必须等于本轮已确认父级的 node_token；既有页父级保持写前值；同公司同职位无重复；合并文档覆盖本轮全部公司且没有额外建分公司页。原主页与双通用页的 URL 不变。
2. **范围保护：** 通用学生版与老师版的正文、顺序、附件／媒体和手工内容与写前一致；若其间有别人编辑导致版本变化，逐项判断变化来源，不整页回滚覆盖他人更新。
3. **正文内容：** 对照内容合同逐项覆盖；各公司研究、核心职责、重点示范、案例及任务有可使用的正文；逐项核产品/用户/收费/渠道、任务/交付/指标及案例推演，短轮次速读与完整底稿相互对应。只有用户限定短稿时才不按全套覆盖验收。
4. **格式与事实：** 无重复文档级标题、坏图／空媒体、错姓名、教师内部字段；新图逐张目视检查；关键事实、指标口径与来源完整。
5. **交付状态：** 必需项失败则继续在授权范围内修正；确实受阻时列出已完成、缺项和最小所需信息。不得把目录修好、8 道 HR 问答或命令成功等同于完整专岗验收。

## 最终表面视觉验收

### 成图质量门

制作或重做讲解图前，为每张图写出读者问题、关系与主阅读路径。已安装共享视觉 Skill 时读取其 `references/figure-quality.md`；未安装时执行下列同等判断，不把缺依赖变成跳过审图的理由。

逐图检查并记录五项具体观察：标题与结构是否一致、节点与连线逻辑、主次阅读层级、实际宽度下可读性、图比相邻正文增加的解释。仅把正文塞入框、把原生表格截图、反复套同一构图时，重新设计关系表达；有效的比较表不必为了图片数量再出图。飞书阅读材料中的讲解图、流程图、关系图和方法总览默认使用飞书原生画板，嵌入对应正文并紧邻讲解；不再默认生成讲解图片。先锁定读者问题、准确文案、关系和阅读路径，再实际应用 `impeccable` 的 Read 模式处理信息层级、字体、对齐、间距、留白和配色。图只承担有助理解的关系，不把正文缩写塞进框，不做大字海报或装饰图凑数。逐字逐线检查，并核对原生节点、画板导出及正文实际阅读宽度；非空token、上传成功或导出成功均不替代视觉验收。非飞书文件使用已验收画板的清晰导出或适合该格式的图；真实统计图可用精确计算工具。用户明确要求图片或确需照片、插画时另选图像工具，并保留相同质量门。不能以换工具代替成图判断。

在 `visual_contract.quality_review` 为每张图保留读者问题、显示宽度、目标面证据、五项观察、`pass`／`revise`／`unverified` 与未解决问题。整体审稿把全部讲解图一起看，检查统一性和各图是否选对形式。全部必需图均通过后才结清；共享校验器仅核记录，不评美学。只修某图时保护其余图，整体优化时不得只验新图。原始招聘截图属于来源，保持原件。

### 最终显示

开始正文图片验收前，读取 [feishu-image-browser-recovery.md](feishu-image-browser-recovery.md)，采用其中的逐图清单、故障恢复顺序与网页证据记录；不要在后台超时或全屏空白上反复循环。

完整专岗页使用图解时，结构读回和最终渲染缺一不可：

1. 读回每张正文图片及保留画板的非空 token 或 `src`、标题／图注、所在章节和块顺序，确认业务闭环、证据矩阵与 Case 路径的图片均直接出现在对应章节，没有错位或无意义重复。仅有首屏预览和直达链接判定未完成。
2. 逐图在飞书实际页面打开对应章节，检查图片加载、正常桌面缩放下的字号、完整边界、分支与底部内容；不能只检查首屏或媒体标识。
3. 完整新稿或大幅改稿将最终学生可见页面导出为 PDF，或使用能覆盖同一完整表面的等价渲染；不能只看编辑器中的源码、Mermaid 语法或 CLI 成功回执。仅局部嵌图修复时，完整检查本轮所有受影响章节与每张图片，并对其余块做写前写后比较。
4. 逐页或逐个受影响章节检查裁切、重叠、跨页断裂、最小字号、表格宽度、图例、图文距离和正常桌面缩放下的可读性。
5. 任一检查失败时修正并重新完成本轮适用范围的检查。
6. 把检查方式、页数／章节、已检查范围、检查项和未解决问题写入 `visual_contract.render_qa`，运行共享 manifest 校验。空媒体、缺图、缺来源、未覆盖本轮范围或仍有问题时保持未完成状态。

通用模拟面试的全册校验器包含双端、三岗位卡等规则，不可拿它的旧页错误驱动本 Skill 重写通用材料。专岗应验证单个目标的内容、父子关系和原页保留；必要时做只读检查，但明确其检查范围。

最终给本轮实际目标链接、当前 revision_id、实际修改与只读核对对象、本地备份/明确未触碰对象、原页保留结果和影响使用的待确认项。不输出本地母稿，除非用户明确要求本地副本。
