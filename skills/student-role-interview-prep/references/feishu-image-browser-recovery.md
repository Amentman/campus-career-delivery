# 飞书正文图片验收与浏览器故障恢复

用于专岗页正文图片的实际显示检查，以及后台超时、全屏空白、离屏元素、剪贴板冲突后的续接。只补图片验收时，复用原页和已有有效证据，不重新研究公司、重写正文或再建页面。

## 直接执行的顺序

1. **先锁定原页与图片清单。** 用本人身份经 CLI 读回目标、父级、修订号和正文；为每张图记录所在章节、block ID、非空媒体 token／`src`、图注及顺序。已有下载哈希和完整导出可以复用，但先核对当前正文是否仍一致；它们不能代替网页逐图检查。
2. **先用后台视图。** 选当前可用的能力；UI 操作遵循当前工具文档。需要前台时复用本任务已有的明确授权，不再确认同一范围；没有授权时按全局规则处理。短暂前台授权不代表允许改账号、权限、浏览器设置或其他任务。
3. **先判断通道，再判断图片。** 核对目标网址、选中标签、当前截图和正文状态；状态树与截图不对应、整页空白或点击离屏时，先按下表恢复。恢复后必须重新观察，不能用旧索引或旧截图接着操作。
4. **按目录逐图查看。** 优先点击真实目录中的对应章节，再在正文区域滚动。正常桌面缩放下检查完整边界、字号、文字、箭头、分支、终态、底部说明和图注与讲解的距离。长 JD 分段连续滚动，覆盖顶部、职责、资格、底部与图注；一屏放不下本身不等于图片被裁切。
5. **只修已证实的问题。** 缺图、实际裁切、字小或错位确认后，在原页按 block 局部修复，再回读并重查所有受影响图片。仅工具截图异常时不重复上传、不改媒体、不新建替代页。
6. **回读后收尾。** 对比验收前后正文、媒体与顺序，核对归属和父级；修订号变化不等于正文变化。记录网页逐图证据和仍未覆盖项。没有新的用户操作冲突时，还原为验收临时改变的窗口模式与原选中标签，保留用户其他窗口和标签；用户重新开始操作时，停止前台竞争，记录未还原项，不抢回焦点。

## 故障速查

| 可观察的异常 | 下一步动作 | 恢复或通过的证据 |
| --- | --- | --- |
| 同一后台 DOM、evaluate、点击或导航连续两次出现相同超时 | 核对一次参数与会话后停止原样重试，切换另一个可用通道；不能靠更换方法名在同一失效通道循环。已获前台授权时可用原生窗口操作 | 新通道能返回目标原页的实时正文与截图，并能完成章节跳转或滚动 |
| Chrome AX 有标题／网址，正文树缺失、截图白屏，并出现 `cannotClickOffscreenElement` 或 `noWindowsAvailable` | 检查原生窗口和“显示”菜单；若实际观察到“退出全屏幕”且本任务已有前台授权，尽早临时退出全屏，再取状态与截图。本次这一操作恢复了显示和滚动，但不是所有白屏的通用根因 | 退出全屏后的同一原页实际出现正文，目录跳转、滚动和截图正常；仍失败就换通道或如实记录阻塞，不继续盲点 |
| `Raise`、选择标签或刷新成功，但截图仍白屏或停在旧内容 | 成功回执只说明动作被接收；重新核对选中标签、网址、窗口模式和实际画面，再决定下一步 | 本轮截图能对应本轮跳转或滚动后的内容；旧首屏不可充当新的章节证据 |
| 新建标签／导航调用超时，结果不明 | 先读现有标签清单和目标网址，确认是否已经创建或导航；只复用唯一目标。Chrome 不支持隐藏控制时，不反复传 `visible:false` | 清单与当前画面一致，没有重复目标标签；不得把“超时”直接当作“没创建” |
| 目标被用户收进 OneTab，或用户切走了当前标签 | 只恢复／选中已观察到的目标链接；不要“全部还原”、关闭其他标签或把新出现的用户页面当作操作对象 | 原目标网址与标题一致；重新取状态后再操作，结束时按上文的无冲突条件还原原选中标签 |
| 中文输入只剩数字、查找结果没更新，或 `setValue` 后没有命中变化 | 改用目录定位与原生滚动。确需查找时，核对焦点、输入值及真实命中；赋值成功不代表触发了网页查找事件 | 对应章节实际滚入视口；输入框值正确仍不足以证明已定位 |
| 原生 `paste` 报用户冲突，查找框出现另一段文本／网址 | 立即停下本次输入，读取最新状态；不导航到误粘的网址，不盲目补按键，更不往正文重试。已有前台授权且用户冲突已消失时，可重新聚焦搜索控件或改用目录；用户仍在操作时退回后台可做的检查 | 目标与焦点重新明确，实际定位成功；剪贴板异常不构成学生账号或文档权限问题 |
| 导出、媒体下载和哈希都正常，但网页无法逐图检查 | 分开记录“媒体／结构已验证”和“网页显示未验证”；保留现有图片，继续可用的恢复路径 | 每张目标图片都获得本轮真实网页显示检查后，才能结清网页验收；PDF 不能自动替代这一项 |
| 受保护页修订变化，或目标修订增加但正文相同 | 比较实际正文／块内容，记录可定位差异。其他编辑只作保留，不整页回滚；无法确认变更来源时明确注明 | 只对已核对的范围声明未变，不能因修订变化误判为本次破坏，也不能声称所有页面都未变 |

所有 UI 操作使用当前提供的 Computer Use 工具；工具会话重置后按其首次调用约定重新进入，不绕到 shell、AppleScript 或其他 GUI 自动化。此表记录判断与恢复顺序，不固化临时 tab ID、AX 索引或未出现在当前文档中的 API。浏览器直达文档地址可能重定向回 Wiki，不保证形成独立验收通道。

## 本轮证据与完成门

在任务临时记录或已有验收 manifest 的 `visual_contract.browser_qa` 中保存：

```json
{
  "status": "passed",
  "checked_sections": ["业务章节", "JD证据章节", "Case章节", "原始材料章节"],
  "checked_images": 4,
  "checked_items": ["loaded", "complete_boundaries", "normal_desktop_readability", "arrows_and_branches", "bottom_labels", "captions"],
  "evidence": [{"file": "browser-case.png", "section": "Case章节"}],
  "issues": []
}
```

数目按当前页实际清单填写，不固定为四张。截图必须是本轮真实页面，必要时记录尺寸／哈希；全屏空白、旧首屏和仅有标题的状态树不算图片显示证据。保存证据只在本地任务记录中进行，不把内部故障排查写进学生正文。

只有清单内图片均已实际查看、必要修复已复验、正文与保护范围已核对，才将状态设为 `passed`。仍有未查看的图片就保持 `partial`，明确具体通道故障与缺项；不要反复停在同一失败动作，也不要用“已打开网页”代替验收完成。
