# 公司基本面与真实业务研究

研究产物要让学生讲清“谁买什么、为什么买、怎样成交和持续使用、岗位负责哪段工作”。先查公司，再写岗位知识和问题。官网简介、几条新闻、通用运营漏斗或页尾链接不能代替业务讲解。

## 研究与正文的对应关系

完整专岗保留独立公司章节；多公司合并时每家公司各有本章内容，开头和结尾再作同口径比较。下面是覆盖合同，正文用连贯讲解和必要比较表，不逐行复制内部检查标签。

| 要讲清的内容 | 需取得的证据与解释 | 如何影响岗位准备 |
| --- | --- | --- |
| 主体、创始人与团队背景 | 品牌与法人/集团关系、成立背景；创始人及与业务有关的团队经历；区分创始团队与现任管理层 | 公司靠什么进入市场，岗位需要理解的产品/行业能力；不由名校或大厂履历推断产品质量 |
| 发展与融资/经营变化 | 关键产品发布、渠道/地域扩展、并购或融资时间线；上市公司看经营披露，未融资或不披露如实说明 | 讲清从什么业务发展到当前状态；融资额、估值、营收和盈利分开，不将融资写成赚钱 |
| 产品与服务层次 | 具体商品/型号、功能、版本或服务套餐；用一个代表产品解释输入、使用过程、输出和限制 | 学生能用真实对象讲工作，不能只说“智能硬件”“AI平台”“海外业务” |
| 用户、客户与付费方 | 使用者、购买决策者、付款者及渠道商分别是谁；什么场景和频率，替代原来哪种做法 | 判断对谁写内容、做培训、收反馈，谁有购买决定权 |
| 价格与赚钱方式 | 当前可查价格、币种、地区、周期、税/运费/促销口径；订阅、硬件、服务、渠道差价或询价 | 比较成交门槛、购买周期和复购/续费；标价不能当实际客单价，询价不能补一个数字 |
| 市场、渠道与实际业务流程 | 重点国家/地区、官网/零售/经销/平台/直销等渠道；从认知到购买、交付、使用、服务的具体步骤 | 指出本岗位的输入、交付、上下游和失败点；经营地区与招聘地点分开 |
| 竞争与选择理由 | 同一用户任务下的具体替代品，统一比较性能/效果、价格口径、使用门槛、渠道、服务或安全 | 用可核事实解释选择条件；不用融资、排名和口号代替比较，不凭公开资料断言“领先” |
| 近期变化、约束与相关岗位 | 新品、市场扩展、经营变化；合规/质量/安全/履约约束；当前官方相关岗位的职责交界 | 说明目标岗与销售、产品、客户成功、售后等如何协作；相关JD用于理解分工，不擅自选岗或投递 |
| 面试转化 | 公司理解、为什么公司/岗位、业务确认问题、具体案例与训练 | 每项高优先级职责都有公司事实、任务、产物、指标和学生证据/知识的对应关系 |

创始人、融资、内部收入或具体团队没有公开资料时，不以猜测填空，也不把整章缩成“需确认”。按下文补查，正文在相关位置一次说明缺口及其影响；继续把已知产品、购买与使用流程讲透。不得把“未查到融资”写成“没有融资”。

## 按公司类型取证

先判断目标岗位实际承接哪种业务；同一公司可有多种类型，只展开相关部分。

| 类型 | 必须深入的真实对象 | 岗位、指标与案例的方向 |
| --- | --- | --- |
| B2B设备/硬件 | 代表型号和规格、操作用户与采购者、演示/试用、经销商/直销、培训、交付、保修/耗材/售后；地域认证与服务条件 | 渠道运营解释培训、线索转交、经销商跟进与售后升级；指标按线索质量、响应、成交周期、培训应用与维修处理设计，不能套消费电商流量漏斗 |
| 消费品/跨境电商 | 代表SKU及用途、适用/禁用条件、当地价格、消费人群、购买理由、平台/零售/独立站、内容、库存与退换 | 内容选题须对应商品卖点、证据与受众；达人合作讲样品、审稿、链接/归因与复盘；转化和毛利/退货/缺货同时考虑，未知投放预算不捏造 |
| AI SaaS/软件服务 | 具体功能、输入输出、使用任务、试用与付费层、个人/团队/企业购买、激活路径、数据权限、模型限制和服务成本 | 产品运营讲首个有用结果、持续使用、试用付费、反馈与Bad Case；区分产品运营与客户成功续费职责；不能把注册、调用次数或准确率直接当业务价值 |
| 平台/内容/互联网业务 | 供需双方、核心任务、分发/匹配、收费或广告方式、交易/履约、内容治理 | 按实际业务选择供给、需求、转化、留存、质量及风控；不同业务单元单独解释，不把集团指标当岗位KPI |
| 其他类型 | 用代表产品或服务走一遍从需求、购买到交付/持续使用的过程 | 根据真实流程推导任务、产物、判断标准和异常，不强行套上表某一类 |

内部KPI通常不公开。正文明确“以下是工作判断口径，实际考核以团队说明为准”一次即可；随后仍要解释指标的分子分母、统计对象、周期、意义、护栏和可能误判。不要在每道答案重复声明。

## 取证顺序与不足时的继续动作

1. 用官方JD/邀约确定主体、职位编号、职责及业务线；再查公司官网的About、团队/治理、产品详情、定价、帮助/开发文档、服务政策、新闻及官方招聘。不要读完首页便停止。
2. 按公司实际类型补查：上市披露/监管文件；官方融资或投资方公告；创始人公开访谈；渠道手册、经销目录、官方店铺和地域站点；软件更新、安全/隐私/使用文档。再用可信行业/财经媒体交叉核对；技术结论优先官方技术文档与论文。
3. 竞品使用竞品自己的产品/定价/服务资料，按同一地区、时间和购买口径比较。社区或招聘镜像只作线索，不能单独支撑关键事实。
4. 关键内容查不到时，内部来源账本记录：查的事实、查询词、已查渠道/页面、访问日期、得到什么、为何仍不确定、下一条有价值的线索。区分来源缺失、登录/权限受阻和真实未披露。对同类无增量结果停止机械搜索，换与该事实相关的来源类型。
5. 本轮可访问的相关官方渠道及有价值的交叉来源仍无结果时，保留准确未知和影响；交付已证实业务及可教的方法。只有主体/JD不明导致目标可能完全错误，才暂停依赖写入并问关键问题。不要把必须自行调研的信息逐项交回用户补齐。

不设固定搜索次数或链接数量代替完成。来源登记按关键事实可定位，含标题、直达链接、发布/统计期、本次访问日期与支持内容；多个页面重复同一宣传不算独立证据。原始JD单列，网页当前有效性与岗位适配分开判断。

动态事实用当前口径；旧年报与新披露冲突时说明变化。价格必须写观察日期。面试时间已知时，在前24小时复核职位、产品名、定价与重大新消息；无法复核标明资料截止日，不写成当前保证。

## 从事实到岗位工作

内部用以下链条组织，不把它原样铺成学生文档的标签：

```text
有来源的公司事实 → 该岗位在什么场景做什么 → 交付给谁什么结果
→ 怎样判断与排查 → 学生哪段证据可迁移/需学什么 → 具体案例与表达
```

**虚构教学例：** 官方资料显示“检测仪通过经销商销售，用户是小型实验室，保修外维修另收费”，JD要求经销商培训。岗位讲解应展开：把操作与常见故障做成培训材料、检查经销商能否演示与区分维修问题、收集无法解决的问题转交售后。培训完成率只能说明参加；可再看演示通过、重复故障和转交信息是否齐全。案例可设“新经销商培训后演示仍失败”，先分产品操作、样本条件、培训理解或设备故障，再分配处理。学生只做过进度表时，以信息整理与跟进能力迁移，不说自己做过经销体系建设。

业务单元未知时先做公司层研究，再按JD候选分支比较用户、流程、岗位交付和指标；实际团队、内部目标和分工留待确认。准备能切换的回答和开场确认问题，不替学生选一个最像的分支。

## 公司模块完成门

实际通读正文与来源后逐项判断；任一关键项失败，继续补写对应内容：

- 学生能否说清代表产品/服务、实际使用者、购买者、价格/收费方式、地域和渠道？必要未知是否有已查渠道与明确影响，而非大片空白或“需确认”清单？
- 公司背景、创始/团队与发展时间线是否已合理取证？相关动态有日期与直接来源；未知没有被编造，融资没有被误作营收。
- 每个高优先级JD职责是否接到具体产品/客户/业务步骤，讲清日常动作、交付、上下游、可解释指标和异常？集团战略没有被冒认为内部KPI。
- 竞争是否围绕同一任务和口径展开？相关岗位是否帮助解释协作边界，避免将别人职责全归目标岗？
- 公司理解、动机、反问和核心案例是否用到了这些事实？把公司名换成另一家后仍基本成立的内容，应重写到具体业务对象和判断。
- 学生能否据此完成一项明确练习，如解释产品购买链、写一个具体内容选题、处理一个渠道/激活异常？只有题库、新闻摘录或通用建议不能通过。

未公开的创始人、融资或团队信息不自动判全文失败；已经完成相关取证、准确说明未知、核心业务与岗位仍可解释时，可交付并报告该局限。文档讲清与学生已练会分别验收。
