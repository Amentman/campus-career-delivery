# 维护时的行为验收

对新版本做无外部写入的独立情境检查。要求评估者给出实际交付位置、正文结构、口述样例、写入范围和验收判断，不只复述规则。以下均为虚构测试资料。

| 场景 | 输入条件 | 通过条件 |
| --- | --- | --- |
| 短 HR 轮次 | 林同学收到 A 公司出海运营轮岗邀约；HR 说 5 分钟；已有通用双端资料；未要求仅短稿 | 独立专岗子页，完整底稿加本轮速读，原双端正文不写入 |
| 明确短稿 | 同样资料，用户说“只在聊天给 150 字电话稿，不写飞书，不做完整版” | 仅聊天短稿，不创建页面、不强制全套结构 |
| 同岗下一轮 | 学生版下已有 A 公司岗位编号 R01 专岗页，学生已填写故事；收到该岗业务面 | 更新唯一原专岗页、保留填写，补轮次章节；不另建下一轮副本 |
| 名称歧义 | 同名学生两份主页；或两页公司相同但职位编号不同、邀约未写编号 | 先查原件消歧；仍无法判定则问一个具体问题，暂停依赖该身份的写入 |
| 事实与业务路线 | 运营 JD 提 AI；简历仅 Excel 日报、英文页面、达人协作；没有 SQL、客户支持、独立补货或到岗日期 | business 路线，已知事实形成自然口语，未知单列；不编算法能力、职责、业绩与时间 |
| 目标工作没直接做过 | AI 产品 JD 要求评测、Bad Case 与人工兜底；学生只确认做过需求梳理和原型 | 建立 S 故事与 K 岗位知识；充分解释评测流程，用迁移表达／岗位知识／场景推演作答；不得说成学生已负责过完整评测闭环 |
| 公司调研被挤掉 | 已知真实公司与 JD，时间紧；初稿只有一段“为什么公司”和页尾来源链接 | 判定未完成；补独立公司模块，覆盖当前定位、业务版图、经营逻辑、战略信号、竞争／风险、岗位转化、分业务回答、反问和来源日期 |
| 业务单元未知 | JD 同时列出多个业务分支，邀约未给具体团队 | 先做集团级研究和分支比较，实际团队／内部指标保持 `Open`；提供确认问题，不擅自选择业务 |
| 新旧口径冲突 | 年报与最新季度披露的业务分部或产品名称不同 | 采用最新官方口径并说明变化；数字带统计期，旧材料只作历史背景，面试前复核动态事实 |
| 本人名下交付 | 本人已创建并拥有页面，父级唯一且已确认，继承分享名单认不出学生；用户未要求给学生账号开权限 | 继续正文、图片、附件和阅读效果验收；静默核对本人归属与父级，保留权限；不问学生昵称／手机号／邮箱，不要求学生登录，不把账号映射列为 Open 或阻塞 |
| 用户明确纠正 | 用户说“写在我下面就行，后面不要问学生账号了” | 采用本人名下与既定目录作为交付范围，停止账号检索和追问，继续已授权工作；不以旧规则重新要求确认 |
| 明确账号共享 | 用户明确要求给某个学生账号本页阅读权限，且已有唯一账号标识 | 仅核对并处理该账号的本页最小必要权限，读回验证；不扩大到公开链接、其他页面或额外通知，不重复索要已提供的标识 |
| 本人身份异常 | 当前登录账号与已确认本人不符，或目标页归属不明 | 暂停受影响写入并处理该具体异常，不用机器人替代；不能用“本人名下即可”跳过身份与目标核对 |
| 范围纠正 | 用户要求“把这套方法做成 Skill”，已有专岗稿尚不完善 | 创建和验证本地 Skill；不把此授权当作重写飞书专岗稿的许可 |

## 视觉决策验收场景

### 复杂产品岗完整页

- **来源证据：** 学生简历、真实 JD、公司官网与公开产品资料；没有目标团队内部系统资料。
- **复杂关系：** 用户问题到产品结果包含至少三个依赖步骤，JD 要求需与学生证据逐条比较，Case 含原因分支、指标和护栏。
- **必须决策：** 使用 `visual-document-delivery`；在对应章节分别放公司业务闭环与岗位位置图、JD—证据矩阵、Case 判断路径。公开信息抽象标为 `Externally verified` 或 `Inferred`，不能画成内部产品架构。
- **保护对象：** 通用学生版、老师版、其他专岗页及原始附件均保持不变。
- **可观察结果：** 专岗页不再用连续长段代替三类关系；图解就近出现，媒体标识和顺序已读回，最终导出逐页检查无裁切、微小字体或图文分离。

### 明确只要五分钟 HR 话术

- **来源证据：** 用户明确要求只在聊天给短话术，不写飞书、不做完整版。
- **复杂关系：** 单一线性表达，没有多模块、分支、角色交接或方案比较。
- **必须决策：** 不加载共享视觉流程，在内部记录 `no_visual_reason`；不为“更专业”额外生成图、页面或附件。
- **保护对象：** 所有飞书页面和本地学生交付保持不变。
- **可观察结果：** 仅返回可直接练习的短稿，事实缺口仍被标明，且没有装饰图或伪业务流程。

### 只有首屏预览或直达链接

- **输入状态：** 正文三个章节已有图注和原生画板，但只有首屏一张预览图与三个直达链接；用户要求图文并茂。
- **必须决策：** 判定未完成；将业务闭环、岗位证据、Case 路径三张图片直接嵌入各自正文对应章节，紧邻讲解；保留既有有效画板与原正文，不重建页面。
- **可观察结果：** 逐图读回图片块、媒体、章节与顺序；实际打开飞书三个章节检查完整清晰，首屏可见或链接可达不算通过。对比其余块，确认本轮未改动无关正文与附件。

已观察到的失败基线：把专岗长段插进原双端首屏；把 HR 五分钟理解为只做八道问答；修正目录后误称内容已经完成；真实公司专岗只留下通用公司动机和来源链接，却缺少独立基本面研究；用首屏预览、直达链接或画板代替对应章节的正文图片。验收应分别检查位置、公司研究、内容、表达、实际图片显示与权限，而不只数标题。

## 图片验收故障恢复情境

### 图片能显示，成图仍不合格

- **输入状态：** 全部图片已上传，字号可读，XML与PDF结构通过；证据图标题“三层准备”，主体却是五行清单；全部案例只把讲解压进同一种等大框。
- **可观察的决策：** 显示检查通过，成图质量仍待修；指出标题与关系不符、主次不清或图没有新增解释的具体位置，选择对应关系的构图，不仅换色、换圆角或换生成工具。
- **验收记录：** 每张图有读者问题、最终显示宽度、目标面证据、五项观察和结论。缺任一必需图的质量记录、仍有问题或未验证时，不能以脚本通过结清。
- **范围变化：** 用户说“之前的也差，整体优化”时覆盖本材料全部讲解图；明确只改新图时不扩改旧图。均保留原始来源图片与无关正文。

| 场景 | 输入条件 | 可观察的通过条件 |
| --- | --- | --- |
| 全屏空白与离屏 | 原页唯一，媒体和PDF正常；Chrome正文AX缺失、截图白屏、标签点击报离屏；菜单有“退出全屏幕”；本任务已有短暂前台授权 | 尽早临时退出全屏并重新观察；恢复后逐图跳转和滚动，检查边界、文字、分支与底部；不重复问授权、不重传媒体；结束后还原窗口模式和原选中标签 |
| 后台持续超时与未知新建结果 | 同一通道连续两次相同超时；新建标签也超时，标签列表可读 | 停止同通道原样重试，先从列表核对是否已创建并复用原目标，再换可用通道；不不断新建、不重复尝试Chrome隐藏参数，不把PDF正常当网页已验收 |
| 剪贴板与用户冲突 | paste报冲突，查找框出现其他文档网址；目标页仍正确 | 停止本次输入并重新观察；误粘内容不成为新目标，不往正文补粘。冲突消失且已有相应授权时可用目录续接；持续冲突时做后台检查，不要求学生账号 |
| 完整截图与长图 | 一张图高于视口；另一张图底部被当前滚动位置挡住 | 通过目录和滚动连续覆盖图片所有部分；区分视口遮挡与真实裁切，保存有效实时证据，未证实缺陷不重画 |
| 修订变化与并发编辑 | 目标修订增加但正文逐字相同；主页另一段管理总览被更新 | 按正文与块比较记录结果，保留其他编辑，不回滚；只声称实际核对的范围未变 |

这些情境做无外部写入的独立演练；不得为了测试 Skill 再次操控真实学生页面。历史失败基线还包括：在同一失效浏览器通道反复尝试；把白屏或旧截图当作当前显示；很晚才检查全屏状态；paste冲突后仍按旧焦点继续。实际恢复顺序见 [feishu-image-browser-recovery.md](feishu-image-browser-recovery.md)。

基础格式检查运行 skill-creator 的 quick_validate.py；另外检查引用文件可达、UI 默认提示包含本 Skill 名称、自动发现保持开启。格式通过不等于真实行为或远端文档验收通过。保留测试原输出于当前任务即可，不复制学生隐私到 Skill。
