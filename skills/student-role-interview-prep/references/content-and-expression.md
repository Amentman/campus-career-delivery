# 内容与表达合同

## 阅读顺序与每部分的用途

完整准备按理解公司业务、看清岗位工作、对上履历、组织故事和练习表达展开。短轮次速读放在最前，指向对应正文；用户明确只要短稿时按缩小范围执行。标题与问题数不代替解释。

| 部分 | 必须解决的问题 | 应有产物 |
| --- | --- | --- |
| 本轮速读与用法 | 这轮聊什么、现在先练什么、哪些留作后续 | 已知轮次／形式／时间，短自我介绍，意向与硬条件，优先练习顺序；未知明确标出 |
| 公司基本面与商业逻辑 | 公司背景与发展、具体商品/功能、使用者/购买者、价格/收费、地域/渠道、竞争和相关岗位分别是什么 | 每公司研究章节、代表产品讲解、购买/使用链、事实→岗位任务/产物/指标/案例、动机与反问、来源和截止日；详细合同见 [company-fundamentals-research.md](company-fundamentals-research.md) |
| JD 大白话与匹配结论 | 每条职责日常具体做什么、交付什么、怎么判断做好 | 逐条职责的具体对象、日常动作、交给谁的产物、上下游、判断口径与常见异常；定位依据和差距 |
| JD 逐条证据矩阵 | 这个学生凭什么匹配，哪里需要补 | 要求—原始证据—直接／可迁移／缺口—待补事实；主要经历排序 |
| 产品、行业、业务链与指标 | 学生能否独立解释岗位业务 | 用户场景、输入与输出、业务流程、常见异常、竞品比较维度、必要术语和指标例子 |
| 个人项目地图与故事库 | 哪段经历证明哪项能力 | 每段核心经历的背景、任务、个人动作、交付物、结果、职责边界、失败／取舍、复盘、对应问题 |
| 重点示范稿 | 怎样把真实经历自然说出来 | 短自我介绍、最相关实习、核心项目；无独立项目时用第二段有证据的经历，不能造项目凑数 |
| 核心问题训练工作簿 | 怎样从问题调用故事并完整作答 | 针对 JD 的题卡、关键词、自然参考表达、本人填写区，覆盖动机、经历、协作、判断与硬条件 |
| 岗位案例推演 | 能否把已有能力迁移到该岗位 | 场景、已知信息、必要追问、判断路径、建议动作、验证指标、风险与自检；明确是假设训练 |
| 任务与验收 | 面试前做哪些具体准备 | 优先级—任务—产物—完成标准；区分本轮必练与后续备用，最后列事实待补和来源日期 |

## 专岗图解合同

用户指定的文档与合并方式优先；未指定时，专岗正式交付默认写入学生唯一飞书主页下的独立 `专岗准备｜公司｜岗位` 子页。讲解图默认以原生画板置于对应正文，应用 `impeccable` Read模式；写后读回画板token、原生节点、位置、导出和学生端实际阅读宽度。保留已有有效媒体；导航链接、附件与源码不能替代正文可见画板。没有复杂关系且用户明确限定的短输出可不配图，但记录具体 `no_visual_reason`。

完整专岗页存在复杂关系时，使用 `visual-document-delivery` 先完成视觉规划。默认检查以下三个专业图解槽位，只有关系真实存在时才生成：

1. **公司业务闭环与岗位位置。** 讲清用户／客户、关键输入、公司如何创造价值、岗位承接哪一段以及主要上下游。公开资料只能画成公开业务抽象；没有目标团队内部资料时不得画成内部产品架构。内部区分公开事实与整理推断，正文在图注一次说明公开业务抽象，不贴事实分类标签。
2. **JD—学生证据矩阵。** 把职责、日常任务、直接证据、可迁移证据、缺口和待确认项放在同一视图。矩阵允许清楚显示“无证据”，不能用相似关键词把缺口升级成学生经历。
3. **Case 判断路径。** 在案例章节展示“已知信息 → 必要追问 → 原因分支 → 建议动作 → 结果指标／护栏指标 → 风险与复盘”。这是岗位迁移训练，正文说明假设条件，不得写成学生曾在原公司实施。

图解紧邻其解释章节：业务闭环放在公司与岗位说明之后，证据矩阵放在匹配结论处，Case 路径放在案例题正文之前。图内使用短标签，完整解释回到正文；不得把三张图集中堆到首屏或文末。逐张打开对应章节检查实际图片，确认完整、清晰、无裁切，不能只数媒体块或检查链接可达。

用户明确只要 5 分钟 HR 电话稿、150 字话术等短输出，且内容只是线性表达时，不生成图解，在内部视觉合同写明 `no_visual_reason`。短轮次并不自动豁免完整专岗底稿；只有用户明确缩小交付范围才按短稿验收。

## 多公司合并怎样组织

用户要求一份材料时，整份文档是一套准备包：

1. 开头用简短总览比较各公司卖什么、谁使用/付款、目标岗负责哪段、学生先练什么，接章节导航。
2. 每家公司依次讲基本面与具体业务、目标岗位工作、与相邻岗位的交接、学生匹配和缺口、公司专属表达与案例。研究深度由真实业务决定，不强凑等长章节或统一题数。
3. 共用S故事库、硬条件和练习安排只写一次；各公司通过引用故事说明迁移点，不反复粘贴简历、自我介绍和免责声明。
4. 最后比较同名岗位的不同工作及面试准备取舍。例如设备渠道运营重经销培训/线索/售后，消费品内容运营重商品/人群/内容/成交，SaaS运营重有效使用/激活/付费。比较须由本轮来源支撑，不把示例当现成结论。

不把合并理解为把三份薄稿顺次拼接；每家公司都要通过公司研究与核心职责完成门。已有独立页保留原位，不因合并擅自删除、迁移或重写它们。

## 讲清岗位日常与案例

每项核心职责至少有一段可使用的解释：在什么情况下，处理什么真实对象，做什么动作，交付给谁，用什么口径判断，出错后如何排查。相关岗位帮助讲交接边界，不替目标岗承担所有工作。未知内部流程用有依据的岗位方法讲清，不伪装成该团队制度。

指标覆盖实际进入故事和题目的关键判断，解释大白话、分子分母/统计对象、周期、示例、决策意义与误判。实际考核指标未知可一次说明，再继续展开建议口径；不把所有指标都写成待确认。例子数字标为教学示例，不能进入学生业绩。

案例先锁定该公司一个具体产品、用户任务、市场或渠道，再写题面、已知信息、必要追问、至少两种合理原因、取舍、动作顺序、协作方、结果指标与护栏。结尾让学生做一份小产物，如选题及理由、线索交接表、试用异常清单，并给检查标准。运营内容题不能只回答“明确目标人群、优化内容、复盘数据”；应拿具体商品/功能给一个选题，说明面向谁、讲什么、在哪发、怎样防止错误承诺、怎样检验。

学生没直接负责目标工作时，仍充分解释岗位方法，用迁移/岗位知识/假设身份回答。用一次准确的边界说明代替每题重复“没做过/需核实”；不删掉知识，也不编成亲历。

图解形式由关系决定。应用可用的impeccable阅读模式，先有总体阅读顺序，再按案例分支或业务关系补局部图；图不承担正文缩写，解释保留在相邻正文。必需图先生成并目视确认再写入，失败不插占位或宣称完整交付。

## 故事是可复用素材，不是每题重编

为核心故事编 S1、S2 等标记。每个故事至少有：

- **背景／业务问题、目标／任务。** 谁遇到了什么问题，为什么需要做。
- **我的动作、产物与结果。** 亲自处理什么信息、做什么判断、交付什么；有数字时注明来源及统计边界。
- **职责边界。** 独立完成、共同参与、他人负责、尚未确认分别说明。
- **失败／取舍与复盘。** 有证据才写成发生过；无证据则列待补，不能给成功故事硬加冲突。
- **能回答的问题。** 让同一真实故事服务多个追问，而非每题制造新经历。

完整准备将故事映射到常见行为主题：目标、主动带动、信息分析、事实说服、合作、创新、优先级、快速学习；失败与复盘另行覆盖。故事不足时保留缺口，不为凑题数量虚构。实际没接触客户就说明反馈通过谁转达，没负责模型训练就不能说做过微调。

## 岗位知识也要复用，不因“没做过”而删除

除 S1、S2 个人故事外，为岗位核心工作建立 K1、K2 知识卡。每张 K 卡讲清：岗位通常怎么做、为什么这样做、常见例外／风险、指标／验收、与学生已有经历的连接、表达边界。K 卡可以完整覆盖学生尚未直接负责的环节，帮助学生理解真实工作；但它不能被写成履历。

每道题选择清楚的表达身份；内部用S/K核对，学生页只保留帮助练习的提示，不逐题铺事实分类标签：

- **亲历表达：** 引用至少一个 S，用“我当时……”说明真实动作和产物。
- **迁移表达：** 引用至少一个 S 和一个 K，用“我没直接做过完整 X，但在 S 做过相似动作；放到这个岗位，我会……”连接能力。
- **岗位知识：** 引用至少一个 K，用“岗位通常……”解释方法，不伪装成个人经历。
- **场景推演：** 引用至少一个 K，先写明“如果／假设”条件，再给判断路径和验证方式。

这四类不是真实性等级，而是表达身份。内容可以很丰富，身份必须清楚。

## 示范稿怎样表达

让学生拿到能练的自然正文，同时保留真实边界。推荐结构：**先给结论 → 一句业务背景 → 个人动作与判断 → 产物／结果 → 对岗位的意义或复盘**。技术术语必须用具体任务解释。

三个重点示范通常分别练：30–45 秒自我介绍、约 2 分钟核心实习、60–90 秒核心项目。按真实轮次调整并用朗读／录音核对，不能只凭字数宣布达标；未实际录音时写“目标时长”。

示范正文与准备备注分开：正文不混入“简历中记录”“正式面试我会补数据口径”“此处需要证明能力”等作者旁白。已知事实预填，关键缺口用少量准确的〔请补：具体事项〕；若缺口过多，先说明业务并收集事实，不输出全篇空格。示范后另写事实边界、改写任务和目标时长。

证据只有任务标签时，正文直接说已有事实，例如“我做过 Excel 日报，也参与过英文页面相关工作和达人协作。”不要填充成“介绍这段经历时，我会重点讲清楚我做了什么”——这仍是准备旁白，不是经历表达。信息不足就缩短示范，将需要追查的细节写在正文之外。没有口述或录音证据时，将“学生复述并讲清”设为训练验收项，不宣称学生已经掌握。

不要让学生说“熟练掌握、全链路负责、显著提升”替代动作；不把“参与”升级为“主导”。用户意向、地点、薪资、轮岗接受程度和到岗时间只能使用本人确认的事实。

**表达例子（虚构教学素材，不是任何学生的经历）：**
已知事实只有“更新销售日报、发现库存异常、整理异常清单交给运营负责人”。可说：“我主要做销售数据的日常更新，发现库存异常后整理成清单，交给运营负责人判断后续处理。”不能扩写成“我独立优化补货策略并提升销量”。若要形成完整故事，另列待补：异常识别依据、负责人采取什么动作、是否验证结果。

## 学生训练题卡

每题围绕当前学生、当前岗位填写：

```text
问题：具体问法
考察点：学生能理解的一句话
表达类型：亲历表达／迁移表达／岗位知识／场景推演
回答骨架：先说什么、再展开什么
事实或场景依据：S1／K1 的哪项真实动作、岗位知识或假设条件
回答关键词：能帮助脱稿的少量锚点
参考表达：自然、具体、以已知事实预填的口语
我的版本：留给本人改写
检查提示：时长、要补的事实、最容易跑偏的地方
```

题目数量由 JD 和证据覆盖决定。每个高优先级要求有对应故事或训练问题即可，不机械搬一套通用题库。学生页不放内部评分、扣分标准、教师追问答案或审计记录。

案例是迁移训练，不能当成学生在原公司做过的事情。优先选真实岗位会遇到的问题；例如运营岗的销量下降、内容有流量无成交、新品库存与推广冲突。给必要追问和两种可能解释，再要求提出可验证动作，不提供脱离信息条件的万能答案。

## 内容验收问题

1. 学生能否用大白话复述公司业务、岗位日常及自己的匹配理由？
2. 删除姓名后，仍能从具体经历与证据认出这是该学生的材料吗？
3. 三段重点表达能否讲出口，作者备注是否已经移出正文？
4. 每个候选人动作和数字是否能回到原件；例子、团队成果与个人成果是否分清？
5. 能否找到每项核心 JD 对应的故事／问题，以及每项关键指标的解释？
6. 完整材料是否存在，即使本轮只用速读？用户明确只要短稿时，是否如实按短稿交付？
7. 任务是否能以录音、事实表、业务解释或真实体验记录验收，而不是“继续学习”？
8. 公司背景、产品/价格、客户/渠道和竞争是否有当前来源，能转成具体岗位工作与案例？
9. 把公司名换掉后是否仍几乎原样适用？若是，补产品、地区、渠道、交付和取舍。
10. 多公司合并是否有总览、各公司完整解释与差异比较，共用经历是否避免重复？

交付状态分别说明：结构覆盖了哪些部分、哪些关键事实仍待补、哪些内容已能直接练习。只有标题齐全或通用框架齐全时不能标“完整可用”；关键事实不足导致核心故事不能成立时，明确为待补草稿。学生尚未完成真人训练，与文档是否完成写入和内容验收分开报告。
