# 双档案与可用回答

准备围绕两个问题展开：对方准备判断什么、会怎样继续问；学生能用哪些实际动作和产物回应。问题档案与个人履历档案相互索引，最终转成可直接练习的主回答、追问回应和具体案例。

本合同规定内容，不新增存储或写入权限。复用本轮已有文档中的题库、项目地图、S故事与来源索引；内部溯源留在当前任务或已授权内部材料中，学生正文只展示有助练习的部分。不默认另建Base、共享题库、两份本地JSON或额外飞书页面。跨学生只能复用去除个人资料后的问法与知识，不能复用别人的经历和业绩。

## 问题档案：从来源判断追问重点

先完整读本轮JD、邀约、相关真实面试记录和已有题库。离线、合成试跑或用户明确禁止联网时，只整理已给来源，缺项如实保留，不补造链接或日期。明确公司岗位时，定向检索同公司同岗、相近轮次的候选人面经；缺少时扩展到相邻岗位或同类公司，保留适用范围。查不到同岗面经时如实说明，再用JD与学生履历推导准备问题；检索不再产生有效线索就停止扩搜，不能为了声称“有真题”采用无出处题单。

每个问题保留稳定题号，记录以下信息；不必把这些字段逐项铺进学生题卡。

| 信息 | 具体记录 |
| --- | --- |
| 来源与时间 | 用户原始记录、候选人自述面经的链接和发布日期／面试日期、JD条款、教学推演；未知日期不猜年份 |
| 适用范围 | 公司、岗位、职级、轮次；与当前目标相同或相邻；同一原帖的搬运只算一份来源 |
| 问法与考察意图 | 原问题或保留含义的转述；要判断的具体能力或事实，不能只写“综合能力” |
| 追问路径 | 主问题后最可能追哪项动作、产物、选择理由、例外、指标或归因；真实追问和准备推演分开 |
| 回应依据 | 对应S故事、K知识及具体产物；没有依据的亲历题保留缺口 |
| 练习顺序 | 根据JD重要性、来源相关性、学生薄弱处和本轮时间判断先练什么，说明理由 |

“提问偏好”写成有依据的准备判断：**哪类问题值得优先准备→依据是什么→通常会怎样继续问→学生用什么回应。** 同岗多份独立面经中的重复主题，可以支持准备重点；相邻岗位面经主要帮助判断追问方式，不能直接证明本岗位题目、频率或本轮面试官风格。没有面试官信息时分析岗位会怎样判断人，不虚构某位面试官爱问什么，也不给无数据支撑的命中率。

无明确公司岗位的通用模拟，按已确认方向或明确标注的代表性岗位判断常见追问重点；不制造一场不存在的公司面试。用户只改某一题或只续显示验收时，只更新相关记录，不重跑整个研究。

## 个人履历档案：把简历压缩句展开为可调用事实

逐段核对当前简历、学生原始讲解、实际问答和可用产物，复用既有P项目卡、S故事编号。对每段核心经历写清：

- 谁在什么情况下遇到什么问题；输入是什么，学生负责哪一步。
- 本人实际动作与判断，做出的文档、清单、规则、原型、测试记录等产物。
- 结果原话；数字的定义、基线、样本、周期、来源和归因，查不到的部分集中列出。
- 本人、团队和其他角色分别负责什么；发生过的取舍或失败需要实际材料支持。
- 能回应哪些主问题与追问；哪类说法超出了这段经历能支持的范围。
- 学生目前能否解释这段经历；没有实际口述记录时写成待训练，不能以成稿流畅推定已经掌握。

同一故事可以回答贡献、取舍、协作和结果等不同问题；每次选取与问法有关的动作，不整段复制。K知识补充没直接负责过的岗位环节，但与本人履历分开。不要给成功故事硬加争执、失败、领导动作或精确数字。

两份档案双向核对：每道核心题能找到对应经历或知识依据；每段核心经历能找到训练题。新面经、新轮次或新产物到来时增补原编号和来源，修正受影响的判断与回答，保留真实面试原问原答，不把后写的参考答案覆盖成历史回答。

## 把档案转成能说出口的答案

每道训练题先提供一份可用主回答；追问练习也要有答案。核心题通常走两层：先追动作与产物，再追选择理由、失败处理、结果归因或责任。两层要沿前一答继续问，不能只是并列放两个泛问句。题数由职责和证据覆盖决定，不照搬某次样例的数量。

自然口述可以有不同节奏，但要回答当前问题，给出具体对象、动作、判断和产物／结果。技术题须解释机制或数据流，业务题须说明对象和选择，案例题须给出在已写明条件下推荐的具体方案、取舍及验证方式。若题目要求举例，直接展开有依据的例子；不要让学生说“我会举一个例子来说明”。

事实不全时分情况处理：

| 情况 | 交付方式 |
| --- | --- |
| 动作和产物已确认，缺效果数字 | 先讲清动作与产物；缺失数字集中待补，不凑提升幅度 |
| 缺口会改变责任或故事本身 | 不完成虚构的亲历叙事；明确哪段暂不能讲，改用另一段已证实经历，或给岗位方法／假设回答 |
| 岗位方案题没有内部条件 | 写明必要假设后完成一版方案，解释条件变了会怎样调整；不只列“进一步调研” |
| 薪资、到岗等个人决定未知 | 不代替学生承诺；给澄清问法，集中提示本人决定 |

先写可用正文，再安排改写、录音和脱稿练习。“我的版本”可选，空白区、〔请补〕、STAR提纲或“从用户／技术／商业三方面分析”均不能替代答案。缺项不要在每题重复提醒，真实限制只在影响回答的位置说清。

### 合成示例：怎样从事实接住追问

以下为虚构练习素材，不属于任何学生：某实习生依据商品资料巡检页面规格字段，整理缺项清单交给运营负责人；本人没有修改页面权限，材料没有转化数据。

**主问题：你在商品页面优化里具体做了什么？**

“我负责核对页面上的规格字段，依据是已有商品资料。发现漏项后，我把商品、缺少的字段和对应资料整理成清单，交给运营负责人处理。我的交付是让对方能定位哪一页缺什么；页面修改和上线由负责人完成。”

**沿这份回答追问：怎样知道优化有效？**

“目前能确认的是交付了缺项清单，材料里没有修改后的转化数据。如果要验证，我会先检查清单里的缺项是否补齐、内容是否准确；再和负责人看用户是否还在问同类规格问题。销量有没有变化，要另外核对，不能直接归到这次补字段上。”

**继续追问：如果销量确实涨了，就算你带来的效果吗？**

“还不能这样判断。同期价格、流量来源或促销都可能变。我会先确认页面改了哪些内容、前后统计条件是否一致，再看与这些规格相关的咨询或购买行为有没有变化。没有对照时，可以说明期间观察到上涨，不能说是我的工作单独造成的。”

这段示范交付了具体答案，同时保留权限、指标和归因边界；没有把“提升转化”填成未经证实的个人结果。

## 完成前实际走一遍

写前和写后读回均检查本次适用范围：

1. 从核心职责找到准备重点、问题及来源，再找到可用履历／知识；反向也能查到题号。
2. 选择不同考察方向的核心题，读完主回答后继续问两层，核对每一答是否具体且有依据；不能只数题或检查标题。
3. 逐段朗读式审稿：删掉空泛能力评价、作者旁白、重复免责声明和学生解释不了的术语。未实际录音，不声称时长或脱稿达标。
4. 检查是否存在只给问题、回答框架、待补表或改写任务的核心题；若缺事实阻止作答，准确交代该题缺口，其他可完成内容继续。
5. 新增事实与原件逐项对应；教学例子、未来方法、团队成果和本人结果始终分清。机器校验只能发现结构缺项，不能证明内容真实、自然或学生已经会答。
