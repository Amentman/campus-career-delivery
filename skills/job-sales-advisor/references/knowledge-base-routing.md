# Obsidian 求职陪跑知识库路由

## 目标

每次销售任务都先从当前知识库取证，再结合客户聊天做判断。知识库用于提供产品事实、品牌语气、客户共性、案例证据和交付方法，不能替代对当前客户的诊断。

## 定位知识库

1. 优先使用用户本次指定的知识库路径。
2. 否则使用 `<KNOWLEDGE_BASE>`。
3. 路径失效时，在当前工作区执行：

```bash
rg --files . | rg '(^|/)我的知识库/README\.md$'
```

找不到时退回本 skill 的参考文件，不要假装已经读取知识库。

## 每次任务的最小预检

1. 读取知识库根 `README.md`，确认目录、使用方式和当前待补项。
2. 从客户原话提取 3-6 个检索词，例如 `价格`、`保 Offer`、`导师`、`算法`、`留学生`、`项目背调`、`家长`、`投递没反馈`。
3. 在 `01-老板说明书` 至 `06-内容生产库` 中检索；不要默认搜索 `00-录音整理`：

```bash
rg -n -i '关键词1|关键词2|关键词3' \
  '知识库路径/01-老板说明书' \
  '知识库路径/02-产品库' \
  '知识库路径/03-客户需求库' \
  '知识库路径/04-素材案例库' \
  '知识库路径/05-方法论库' \
  '知识库路径/06-内容生产库' \
  -g '*.md' \
  -g '!**/00-产品原始资料/**'
```

4. 打开足以支撑本次回复的直接相关文件，至少提取一条库内依据；必要事实不足时继续定向读，不机械凑文件数。不要只看文件名或搜索摘要就下结论。
5. 生成对客回复前，内部区分：
   - `客户事实`：来自本次聊天、简历或用户补充；
   - `库内依据`：来自知识库的产品、案例、原话或方法；
   - `待核验`：动态信息、未授权案例、冲突口径或缺失数据。

| 销售问题 | 优先读取 |

| 产品档位、价格、导师、4V1、项目、背调、结果保障、服务边界 | `02-产品库/产品卖点.md` |
| 交付流程、陪跑包含什么、过程如何可视化 | `02-产品库/交付体系与资料地图.md`、`05-方法论库/求职陪跑交付SOP.md` |
| 客户痛点、家长问题、行动力、导师响应、课程难度 | `03-客户需求库/客户画像与高频问题.md` |
| 职业规划、方向收敛、能力缺口、时间线 | `03-客户需求库/求职规划需求图谱.md`、`05-方法论库/求职规划方向地图.md` |

## 事实优先级

1. 用户本次提供并明确为最新的合同、报价或正式口径。
2. 知识库 `02-产品库/产品卖点.md` 中标注日期的当前确认口径。
3. 知识库其他提炼文件。
4. `02-产品库/00-产品原始资料` 中的来源层，用于追溯，不自动视为当前口径。
5. 本 skill 的模板、旧销售物料和 `sales-agent`，仅用于流程与表达风格。

同层冲突时用日期更新且明确确认的来源；仍无法判断就标为待确认。

## 销售抓手选择

- 每次只选 1-2 个最能回答当前顾虑的抓手：一个事实，必要时再加一个案例或交付动作。
- 客户问“贵”时，先定位需要解决的求职损失和交付链路，再谈档位；不要堆团队数字。
- 客户问“靠谱吗”时，优先用可验证流程、导师匹配和准确状态的案例；不要只喊专业。
- 家长担心过程失控时，优先讲阶段目标、进度复盘、责任人和风险预警。
- 客户担心结果时，先讲合同对应的结果边界和本人配合义务，再讲团队支持。
- 客户背景与案例不完全相似时，只借用方法，不暗示能复制结果。

## 隐私与证据边界

- 默认不读取 `00-录音整理`、真实学员表、原始录制或合同。
- 必须读取原始材料时，只取完成任务所需的最小片段，不输出姓名、联系方式、访问密码和未授权结果。
- `HC`、实习 Offer、正式 Offer、转正 Offer 分开表述；过程案例不包装成上岸案例。
- “基本零退费”等缺少分母、周期或口径的数据不直接对外使用。
- 公司池只代表长期匹配方向，不代表当前有 HC。
