# 求职规划模板

用于销售咨询中的方向建议、规划案例学习和顾问讲解。正式／完整学生规划、可归档规划文档由 `delivering-student-career-plans` 主导，使用其完整合同；本模板只提供销售侧输入与表达参考，不替代正式规划。普通微信回复仍优先短。

## 交付对象与语态

先判断输出是顾问／对客沟通稿还是正式学生规划；后者转正式规划 Skill。下文学生表述只供已有正式规划的销售表达适配，不另起一套正式交付。

- 用户说明“给学生直接做规划／规划文档”时转正式规划 Skill；“由我讲解”仅要顾问沟通稿时按本次范围输出。引用已有正式规划时，使用第三人称或无主语表达，称为“候选人”“该方向”“本阶段”，或者直接陈述判断。
- 学生交付版使用正式规划文档语态，不写“你应该”“同学”“我看完后认为”“下一步建议你”等对话或命令句；不加入销售推进、服务介绍和顾问讲解词。
- 学生交付版的建议写成标准化条目，如“建议优先考虑……”“准备重点包括……”“阶段目标为……”“可补充……项目”。
- 岗位名称和章节标题优先使用中文。仅保留必要的技术名词、工具名和官方职位名称，首次出现时补充中文含义，避免连续使用中英文同义词。
- 只有用户明确要求“怎么跟学生说”“可发送话术”时，才输出第二人称沟通稿。

## 信息输入

先提取这些信息，缺失时只问会改变判断的关键项：

- 背景：学校、专业、学历、毕业时间、应届身份。
- 经历：实习、项目、校园、作品、竞赛、论文。
- 技能：SQL、Python、R、Excel、数据看板、AI 工具、英语、小语种、内容/视频/设计。
- 偏好：行业、岗位、城市、薪资预期、稳定/成长、是否接受销售/运营/出海/快消。
- 性格：沟通强、表达强、喜欢挑战、抗压、是否愿意跑业务和跨部门协调。

## 规划结构

### 默认核心表

职业规划默认先输出这张表，不要先写大段市场分析：

| 优先级 | 行业与岗位 | 为什么适合 | 公司池 | 怎么准备 |
|---|---|---|---|---|

- `优先级`：使用主攻、保稳、拓展或差异化。
- `行业与岗位`：行业和具体岗位必须放在一起，不能只写“互联网”“产品”。
- `为什么适合`：必须引用候选人的学校、专业、实习、项目、技能或偏好证据。
- `公司池`：给一组长期匹配的目标公司，并注明不代表当前有 HC。
- `怎么准备`：先看真实缺口，写深挖既有经历／知识训练／必要补充项目的具体模块、产物和验收，再关联简历或面试动作。社招或成熟履历不强制补新项目。

“怎么准备”示例：

`补一个“小红书新品增长”项目，完成用户洞察、竞品分析、内容矩阵、KOL 策略和转化漏斗，形成营销方案与数据复盘；同步重构品牌营销版简历。`

不要只写“补平台指标”“提高英语”“准备一份案例”。不要另起脱节的补项目方案，示例仅适用于已确认存在该项目缺口的学生。

学生交付版将表头调整为：

| 优先级 | 行业与岗位 | 匹配依据 | 目标公司池 | 准备重点 |
|---|---|---|---|---|

其中“准备重点”写成客观方案，不向学生发号施令。示例：

`建议补充“航空故障归因分析”项目，覆盖数据清洗、文本聚类、误差分析和可视化看板，形成技术报告与演示成果；同步制作应用数据分析版简历。`

### 1. 核心定位

用一句话定义候选人，不要堆标签。

学生交付版格式：`候选人的核心定位为：【行业/场景】+【能力】+【岗位方向】的复合型候选人。`

示例：

- 医药 + 数据 + 商业：具备医疗健康行业理解的数据运营/产品运营候选人。
- 商科 + 英语 + 电商：适合出海运营、跨境电商和海外增长的业务型候选人。
- 内容 + 活动 + 用户：适合品牌内容、新媒体运营和用户增长的传播型候选人。

### 2. 优势与短板

优势只写可用于求职转化的点：

- 学历/专业背书。
- 可迁移实习。
- 能落到岗位职责的项目。
- 工具和语言。
- 性格与岗位匹配。

短板要写成可补强动作：

- 目标太散 -> 收成主攻、保稳、拓展。
- 互联网经历不足 -> 补产品/运营/数据项目。
- 数据只有工具无业务 -> 补指标体系、异常归因、A/B test、用户分层。
- AI 只有兴趣 -> 补 AI 应用项目或 Agent 工作流。
- 出海只有英语 -> 补海外市场、KOL、本地化、跨境平台案例。

补项目时必须遵守真实性边界：只能写为项目、实训或作品集，不能虚构成公司实习、真实客户项目或编造业务结果。

### 3. 方向优先级

使用 `主攻 + 保稳 + 拓展`，不要写“都适合”。

- 主攻：短期胜率最高、和现有经历最贴的方向。
- 保稳：岗位面更宽、容易拿面试的相邻方向。
- 拓展：上限更高或更符合兴趣，但需要补项目/实习。

每条方向必须包含：

- 为什么适合。
- 适合岗位。
- 适合行业/公司类型。
- 需要补什么。

完整报告或家长版在本节后增加“主攻—保稳—条件性拓展”路线图，展示每条路线的现有证据、补强动作、进入条件和换线条件。路线图使用 `visual-document-delivery`，并把建议、计划与已确认经历分开；默认核心表仍须独立成立，不能只交一张图。

### 4. 推荐岗位池

按“岗位名称 + 岗位逻辑”输出，不要只列公司。

常用分组：

- 互联网：数据运营、策略运营、产品运营、用户研究、产品助理、数据产品助理、商业化运营。
- 出海：海外运营、海外增长、跨境电商运营、海外营销、GTM、海外渠道。
- AI：AI 运营、AI 应用增长、AI 产品助理、模型评测、AI 解决方案助理。
- MKT/快消：品牌市场、消费者洞察、内容营销、渠道/KA、管培。
- 咨询：数字化咨询、医疗健康咨询、数据咨询、行业研究。

### 5. 行业补充

行业信息要服务于规划，不要写成百科。

写法：

- 先说行业为什么有机会。
- 再说岗位真实做什么。
- 最后说候选人怎样匹配和怎样补强。

避免：

- 不要承诺薪资或 offer。
- 不要把动态 HC、扩招、薪资写死。
- 不要用“完美匹配”“必然适合”。

### 6. 时间线

根据毕业时间输出 2-4 个阶段：

- 立即：方向确认、现有经历核对，按准备程度安排简历与投递；必要项目仍标规划／进行中，不写成已完成成果。
- 1-2 个月：实习/项目落地，形成可讲案例。
- 秋招/春招前：岗位池、面试题、作品集、复盘。
- 入职前/实习中：职场沟通、项目复盘、转正/下一段实习。

每个阶段只给 2-3 个动作。

完整报告可将时间线与公司池／投递漏斗组合阅读：只有读取真实投递台账时才使用实际数量；没有台账时仅展示阶段与判断条件，不伪造转化率。动态招聘窗口和 HC 标明核验日期，公司池仍表示方向而非当前招聘承诺。

### 7. 简历重构

按实际方向数和表达差异给简历建议，不机械新增第二版：

- 主攻版：围绕最核心方向重写。
- 拓展版：围绕第二方向或差异化方向重写。

写明每版突出什么：

- 数据运营版：SQL、指标、看板、VOC、用户分层、异常归因、业务建议。
- 产品运营版：用户需求、竞品、功能反馈、项目推进、数据复盘。
- 出海版：英文、海外用户、内容本地化、KOL、跨境平台、GMV/ROI。
- AI 版：AI 工具、Agent、RAG/评估、垂类场景、效率提升。

### 8. 服务化收束

仅当输出给销售或顾问内部使用时，最后自然收束到服务价值；学生交付版省略本节：

- 方向判断：帮学生把主线定清楚。
- 简历重构：做不同岗位版本。
- 项目补强：补互联网/出海/AI/电商项目。
- 投递复盘：按岗位反馈调整简历和岗位池。
- 面试准备：准备行为面、业务案例、数据题、群面/案例面。
- 实习中复盘：帮学生复盘沟通、任务拆解和成果包装。

表达要稳健，不说“保证拿 offer”。

完整顾问或家长销售说明可增加“证据补强（深挖现有／必要项目） → 对应简历 → 投递台账 → 面试案例 → 复盘调整”的交付路径，标清每一步的产物和验收。学生交付版保留行动逻辑，删除销售施压语言、内部价格和成交信息。

## 输出模板

### 微信短版

```
同学我看完你的背景后，感觉你不是要泛泛地投【大方向】，而是应该先把主线收成【主攻方向】。

你的优势是【优势1】、【优势2】和【优势3】，所以主攻可以看【岗位1/岗位2】；保稳可以看【岗位3】；拓展可以看【岗位4】，但这条需要补【项目/实习/面试能力】。

下一步建议先做两件事：一是把简历改成【主攻版】，二是补一个【项目/案例】，这样后面投递和面试会更有抓手。
```

### 完整规划版

```
背景概述：
核心定位：
核心规划表：优先级｜行业与岗位｜匹配依据｜目标公司池｜准备重点
不建议作为主线的方向：
简历版本规划：
投递节奏/应届身份：
近期重点事项：
待确认信息：
```

## 质量检查

- 是否把方向收成主攻、保稳、拓展。
- 是否解释了“为什么适合”。
- 是否给出了具体公司池，并说明不代表当前 HC。
- 每个方向的“怎么准备”是否包含具体补项目、项目模块、产出和简历/面试用途。
- 是否给了下一步动作和时间线。
- 是否避免把项目虚构成实习或真实业务结果。
- 是否避免绝对承诺、固定薪资和过度大厂化表达。
- 学生交付版是否全篇避免第二人称、聊天开场、命令句和销售话术。
- 学生交付版是否优先使用中文岗位名称，并控制不必要的中英混杂。
- 完整报告的路线图、漏斗、交付路径或时间线是否只在关系确实复杂时使用，且未替代五列核心表。
- 图解是否脱敏、事实状态清楚，并完成最终格式逐页视觉验收；短微信回复是否保持无图。
