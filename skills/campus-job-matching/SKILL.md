# 岗位筛选与复核：校招、实习、社招

<!-- skill-workflow-link -->
[查看完整流程图与操作说明](references/workflow.md)
<!-- /skill-workflow-link -->

首次供团队成员使用时，先读 [团队配置与依赖](references/team-setup.md)，只配置当前任务所需能力。

本 Skill 是选岗的唯一维护入口；从本次实际加载的目录解析引用与脚本。方向来自学生本次意向，不内置产运白名单或财务、技术等通用禁选方向。

合格岗位必须有**本人条件匹配、当前岗位存在、对应申请/沟通入口的核验证据、最新简历×完整JD终审通过**。入口核验不等于已发送消息、简历或正式提交；报告实际核验范围。

## 首次使用与能力

公开检索需要当前可用的网页读取或后台浏览器；离线质检与自带测试只需要 Python 3。飞书读写和共享池检索另需已安装、已登录的 `lark-cli`。安装本目录不会安装工具、登录账号或创建投递表。首次查询共享池或写入飞书前读 [运行配置](references/runtime-config.md)，登记当前成员的本人身份及实际目标；没有能力时保留明确缺口，不假设作者环境已连通。

## 范围与本人身份

- 选岗默认只读取公开招聘信息并向既定学生表追加合格岗位；不登录招聘账号、索取验证码、勾选授权、发送消息、上传简历或提交申请。后续已明确授权的平台账号只读检查/代投按该次范围执行，不因选岗授权自动发起沟通。仅复盘流程时只读。
- 飞书只使用本人已配置的 `lark-cli --as user`。成员在 `JIHUI_SKILLS_CONFIG` 或 `~/.config/jihui-skills/team.json` 绑定本人的预期 open_id 与 profile；开工静默核对已确认的身份，显示名差异本身不构成异常，不自动切账号、改登录配置或换应用身份。
- 只处理真实登录失效、open_id不符或当前目标无权访问的具体异常；权限/网络错误不代表缺表，不能因此建替代表。不添加机器人协作者。本轮或已有明确授权覆盖建表且学生确无投递表时，按原有格式建在成员已确认的该学生唯一飞书目录。详见 [飞书交付](references/feishu-delivery.md)。
- 人工审核、投递/面试记录、人工备注、既有权限是保护基线，质检结果不能直接覆盖它们。

追加岗位只能在该学生原页面／原投递表末尾去重追加，沿用原默认视图。不得为新增批次另建页面、Base、子表或日期／批次视图；核验信息写入原有备注／字段。只有当前用户明确要求新入口，或完整确认确无原投递表且创建在授权内时，才创建。

## 先锁定输入与历史

先锁定 `search_mode`，新任务明确写入一种模式，不能靠放宽条件混合凑数。姓名、最新简历、方向、城市、用工、排除项、投递表与本次数量共同读取。

| 模式 | 重点条件与渠道 |
|---|---|
| campus 校招全职 | 毕业年月、企业毕业窗口、学历专业；企业官网/指定校招平台优先 |
| internship 实习 | 在校/毕业身份、到岗日、每周出勤与持续月数；有明确毕业窗口再检查，不统一套校招届别 |
| experienced 社招 | 已核实正式/相关工作月数、职责深度、行业、职级、薪资与到岗；按用户流程优先BOSS，其他平台/官网补充 |

社招与实习必须阅读 [模式与平台](references/search-modes.md)；通用毕业窗口规则不能套到无此限制的社招。旧画像未填模式仅为兼容按campus检查，新任务不沿用此隐式默认。

确认哪份是当前简历后记录原件、完整提取正文路径及SHA-256；不能只凭文件修改时间认定最新。当前用户限制优先；不能扩大方向、城市或把实习混入社招工作年限。

能从已有材料查清就自行读取。关键条件仍不确定时保留待核验，继续处理其他候选；校招不能把“27届”换算成所有企业一致的毕业窗口。

追加/“更多”先分页读全量历史，保存record_id与原字段、标准化职位键。**同一学生 × 同一公司最多 3 个岗位**，默认累计已有非空岗位与本轮合格岗位，不能逐批重置。历史已超额保留不动，停止继续添加该公司并报告；只有当前用户明确另定范围时改变口径，并给 `validate_jobs.py` 与预裁剪脚本传入一致的 `--max-per-company N`。不能只改文字、仍用默认3岗裁剪。

## 共享岗位池：先查池，缺口补搜，新岗回收

选岗默认先检索既有共享岗位池，按本生画像核验后计算缺口，再到官网/招聘平台补搜；本轮新发现的岗位通用信息去重回收到同一池。实际入口保存在成员私有配置的 `shared_pool`；优先 `JIHUI_SKILLS_CONFIG`，默认 `~/.config/jihui-skills/team.json`，兼容旧 `~/.codex/campus-job-matching.local.json`。池所有者单独登记 `owner_open_id`，可以与当前成员不同；操作前核对实际 owner、本人登录和访问能力。首次使用或维护回收时读 [共享池操作](references/shared-pool.md)。

- 用 `scripts/shared_pool.py snapshot` 全量读取，再用 `search` 按城市、方向、模式筛选；保存池内候选数、逐岗复核结果和外搜缺口。未配置、身份异常或池不可访问时，记录“共享池尚未检索”及具体缺口；先补配置，或在当前任务明确允许不使用共享池后再公开补搜。不能悄悄跳过、称查过空池或新建替代池。
- 池内命中只代表有历史线索。届别/毕业窗口、在招与申请入口重新核验，按当前简历×完整JD独立终审；不复用上一位学生的匹配结论，不把累计收录数当当前可投数。
- 本轮或已有明确授权覆盖共享池维护时：新发现且有公司、岗位和公共来源链接的条目，去重后可追加为待复核线索；只回收岗位通用事实。学生姓名、简历、个人评价、人工审核/投递/面试状态、私人备注不写入池。来源 record_id 对应关系保留本地私有日志；先清理申请回执、候选人参数和追踪参数，无法还原公共岗位入口的保留异常。
- 学生表继续只接收 `ready`；共享池可以保留 `pending/blocked` 线索并明确待复核，不转写为当前已核验。明确历史已截止/下架的不重新开放。新岗与旧池重复时关联现有记录，不覆盖旧池人工字段。回收失败保存未完成清单并续接，不把它算作已完成。
- 共享池不套“每公司3岗”限额；该限额仍按每位学生的全量个人历史执行。共享池回收不自动发起沟通、投递、改权限或开启定时任务。

## 执行流程

| 阶段 | 动作 | 必须产生的结果 |
|---|---|---|
| 模式与画像 | 完整读简历与限制，锁定校招/实习/社招及对应条件 | 本轮画像、历史快照 |
| 投递表定位 | 查学生子节点及正文/索引的外部Base链接；唯一存在则复用，完整确认不存在才按原格式创建 | 唯一表ID、父链与结构快照；新表初始零岗位 |
| 池内检索 | 全量读共享池，按当前画像筛选；仍逐岗重新核验 | 池内候选、已核验合格数、剩余缺口 |
| 缺口补搜 | 池内复核后仍不足，再到官网/企业指定招聘站及适用平台补搜 | 外搜候选及来源，不先称可投 |
| 定位岗位 | 适配平台，核对企业、租户、ID、详情区域 | 官方原始响应/正文与时间 |
| 逐岗核验 | 共用主体/职责/学历专业/城市/用工检查，加本模式条件；实测表单路径或检查同岗沟通入口 | 分模式checks、JD/入口证据 |
| 候选排序 | 按匹配、学生城市优先级、截止临近排序，预查重复与历史限额 | 排序候选，不删除历史 |
| 独立人岗终审 | 重读本次原始简历、意向与完整JD，不展示初筛分数/推荐理由；逐项核对职责证据、必备/优先项和差距 | 每条final_review与原件/正文/JD/画像指纹；未过不交付 |
| 质检分流 | 统一脚本做最终去重/累计限额与证据检查，关键未知不靠高分抵消 | ready.json及四类逐条报告 |
| 写入交付 | 只映射ready子集，15–25条一批串行 | 飞书批次、CSV及必要截图包 |
| 新岗回收 | 新发现岗位公共事实与共享池去重，串行追加并回读；不搬学生信息 | 池内复用/新增/重复/待核验/回收异常计数和私有日志 |
| 独立验收 | 全量回读新增/历史/字段/证据，实际检查阅读表面 | 业务质检与写入一致性分别报告 |

逐项判定见 [匹配与核验](references/campus-matching.md)，最终匹配复核读 [独立终审](references/final-review.md)；平台采集、证据缓存和借鉴来源见 [来源适配](references/source-adapters.md)。JS页面使用不抢前台的实际浏览器；HTTP空壳不是岗位消失。

## 四种结果

| 状态 | 含义 | 计入合格数 |
|---|---|---|
| ready | 本模式条件、岗位/入口证据、简历×JD独立终审全部通过 | 是；说明表单/沟通与登录核验边界 |
| pending | 关键条件、岗位上下文、证据或时效不足 | 否，独立列待核验 |
| blocked | 验证码、访问限制、网络/TLS/渲染异常 | 否，不能据此判下架 |
| rejected | 明确不符、停招、过截止、错公司、重复或超公司上限 | 否，保留原因与证据 |

截止未公布可保留未知，其余关卡通过不单凭此剔除。发布很久不等于停招。HTTP200、URL变化、通用登录弹窗、online标志、截图存在或飞书写入成功都不能单独证明ready。

## 统一写入前检查

按 [数据契约](references/quality-contract.md) 准备画像、排序后的标准候选与全量标准历史：

```bash
python3 scripts/validate_jobs.py \
  --profile profile.json --jobs candidates.json --existing existing.json \
  --report quality-report.json --ready-output ready.json
```

首次新表也显式提供 `[]` 历史。退出0=全部通过；1=存在其他结果，只可交付ready子集并报告缺口；2=输入错误，先修输入。`enforce_company_cap.py` 可预裁剪，最终仍须含历史的统一检查。

**脚本是离线证据检查器，不访问网页、不鉴定证据真假、不代替语义判断。** 它会检查终审与本次来源的指纹、引用原文、必备缺口和未知项；不证明提取完整或判断正确。不得为通过手填虚假pass、借其他岗位证据或把搜索摘要冒充官方原文。写入前确认ready指纹对应当前画像/岗位及新鲜证据；输入变了重审再重跑。

## 时效、证据与存量

- 核验时间取实际访问并带时区，与企业发布、更新、抓取时间分别记录。交付前当日核验，脚本默认24小时失效；临近截止在当前投递操作前再次核验。
- JD/画像/规则未变可复用初筛分析；每轮最终名单仍须独立终审，原件/正文/JD/意向变化必须重审。是否在招和申请入口必须重新核验，缓存命中不刷新checked_at。失败源只报告受阻与覆盖缺口，不批量判下架。
- 图片、原文和ID对应当前岗位主区域，不用相关推荐或全站页脚作证。截图存在、哈希不同不能代替实际看图。
- 五类事实保持 Confirmed、Externally verified、Inferred、Knowledge supplement、Open；只有Confirmed描述学生动作/成果。导师带教实践不降低真实性，只核对具体证据冲突。
- 存量复核分页读全量，逐条而非抽样；使用 `--mode audit` 生成record_id级问题清单。默认只报告，获准后局部修正；删除另需明确授权。保护历史与人工字段，写后再全量回读。

## 交付与完成口径

学生服务以飞书为主，utf-8-sig CSV、JD/入口截图和证据为备份。按真实表结构映射，不把核验说明塞进URL列、不自动新增字段。缺质检列优先用现有备注/证据入口；无法呈现关键缺口时先准备具体字段方案，解决必要授权，不悄悄省略。

分别报告模式、线索、合格、待核验、受阻、剔除、成功写入和未投递数量；另报池内复用、外搜、新岗回收及回收异常。链接类型、表单/沟通入口、数量缺口、截止未知、人工字段保护、旧岗位未覆盖范围都要说清。BOSS等平台分别记录“已选岗/已发起沟通/已发送简历/收到回复”，官网提交单列；不把打招呼统一算已投递。各动作须有真实证据；主字段非空数量不能称当前可投岗位数。

```bash
python3 -m unittest discover -s "<本Skill目录>/tests" -v
```
