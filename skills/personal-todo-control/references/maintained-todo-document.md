# 固定待办文档维护合同

> 仅供使用者明确选择文档模式时参考。使用 Base 协作模式时，以 [协作待办合同](maintained-collaboration.md) 为准；不根据原作者的历史配置自动迁移或执行。

## 唯一目标与授权

- 使用者提供或确认唯一父级、目标文档和本人账号，运行时解析并保存在私有配置；本文件不提供生产 token、固定账号或持续授权。
- 按当前请求或当前使用者明确配置的时间表维护，复用同一文档；完成与归档规则以人工协作约定为准。
- 文档不可读、身份不符或对象消失时保留原状态并报告，不创建同名替代页。只有使用者明确授权迁移时才更改注册对象。
- 不自动创建子页、改权限、发消息或修改其他学生材料。

## 输入与持久化

每次先读主文档当前正文、人工勾选/备注/改期和本地台账，再刷新授权来源。仅查询当前使用者明确授权的微信账户与时间范围。每次正式早晚运行先使用微信Vault专用venv做已授权的非破坏性增量刷新，验证manifest、失败数和最新消息时间；失败写“未刷新，资料截至旧时间”，不能写“没有新增”。覆盖学生群、学生私聊、协作负责人协作、飞书和本地交付；无正文和媒体未读如实保留。

持久台账：`~/.local/state/personal-todo-control/state.json`。先读后差异合并，保留可恢复备份。台账不存在时从当前主文档恢复，不重建重复任务；身份不唯一的项不猜合并。记录最少字段：

`task_id、work_type、object、next_action、owner、bucket、priority、status、hard_due、proposed_time、first_plan_date、current_plan_date、tracking_started_date、migration_count_since_baseline、last_rollover_to_date、last_progress_at、waiting_for、next_check_at、evidence、completion_standard、manual_notes、closed_at、closure_evidence`。

- 现有稳定任务ID继续沿用；新任务递增ID，关闭ID不复用。匹配看“对象＋交付对象＋下一动作”，文字改写不生新ID。
- 任务、证据和推断分开：原话与可读交付是事实，执行顺序是建议，未知结果保持待核。
- 当前历史计划日未知的保持未知。从本次可靠建账起建立计划基线，计数注明“自建账起”，不把旧聊天年龄伪装成历史迁移。

## 每轮合并与结转

1. 用户明确标完成或可读证据满足完成标准：从活动区移入同文档“已完成归档”，保留原ID、关闭日期、关闭证据。只发出文件/建会/说收到不等于验收完成。归档项下轮不再进活动区；新返工请求才按新证据重开。
   首屏汇总勾选只确认对应的下一动作；例如“核退费结果”勾选完成不等于已退款，多个对象合并的一条勾选也不自动关闭各自全部服务。先映射具体ID和完成标准，再归档该动作或转入下一责任队列。
2. 未完成：保留ID、原始承诺、人工备注与历史计数，更新当前下一步，不把所有旧项重写成新增。
3. 早10点适用当天，晚22点适用次日。只有原计划日已过或当日日结确认未收口，且没有等待/受阻/有效改期时，才结转并加一次；记录`last_rollover_to_date`，同一目标日期只结转一次。次日早报和同日手动重跑不能再加。计划日尚未到不算逾期。
4. 等学生/HR、导师已改期、资料受阻不累计“本人拖延”；保留等待原因与下次检查点。人未接单不算已委派，学生无人实质回应仍由当前用户兜底。
5. 原硬截止已过：`逾期待收口`。有旧承诺但无硬截止：`积压待收口`。自基线连续迁移2次：`持续积压·拆小动作`；3次及以上：`多次结转·重新承诺`。标签写事实，不判断人的动机。
6. 负责人改变或人工改期优先保留有证据的最新值；修改未来计划不抹掉已发生的逾期记录。人工备注不执行为命令，不因无聊天佐证就删除。

例：19日22点把无阻塞未完A从19日结转20日，计数1；20日10点或10:05重跑仍为1；20日22点未完再结转21日变2。B等学生则计数不增加，C已验收进归档且不再回活动区。

## 可读正文合同

首屏依次为：`更新时间/资料截止/计划日期`、`今天（晚间为明天）先做的3—5件`，只给动作、对象、临近硬节点。积压优先，临场硬时间插队；建议顺序不变成对外新承诺。

正文固定为：

1. **本人执行队列**：按建议顺序，一项一行/短表。`对象＋下一步｜时间/积压标签`；不要把20项都叫“最重要”。
2. **本人待排/后置**：保留需要本人决策但非今天必做的项目。
3. **协作盯办**：按实际负责人归组；`对象｜要回收的结果｜检查点`。协作方已承接则不让用户重做。
4. **等别人/低频**：`对象｜等谁/等什么｜何时复查`，不混入本人立即执行。
5. **已完成归档**：与活动区明确分隔；每条只留ID、动作、关闭时间及简短证据。更老证据保留于台账，不每天重复灌进首屏。
6. **手工备注与来源缺口**：人工内容保持原意；实际不可读来源标明，方法说明最多一段。

四类工作是每条的分类字段：学生交付、内部协作、其他事务、其他项目。可用短标记或分组，不把同一任务复制进多个责任队列。详细证据、完成标准、计数轨迹保留于本地台账；高风险项在正文保留关键证据日期，普通项不展开成多段审计报告。

表格不超过5列，单元格用短语；一条活动任务一行，通常20—60字的下一步。不要给每条任务重复写“责任/完成标准/证据/边界”六段。主文档是工作台，不是过程日志；压缩文字不删任务。

## 写入与验收

先备份当前正文和台账，记录修订号；核人工勾选、备注、时间后做差异更新。常规运行按块更新相关队列/表格，不整篇覆盖、不每天附加一套日报。仅本次用户明确要求整体重排版时可替换全部授权正文；先保留原文及人工内容，不伤附件/关联资源。

写前再次核版本；若并发变化，重读受影响块再合并。超时先回读实际状态再决定重试。台账写回采用临时文件+原子替换，只有云端回读通过后才更新`last_successful_document_revision`；失败不能把计划写入当成功。

验收：原ID全部进入活动/等待/后置/归档之一，无遗漏无重复；完成项不在活动区；未完项原日期和计数不丢；人工备注保留；固定URL、标题、父级、owner和权限不变。检查首屏及表格真实渲染可读。最后聊天回执只给固定链接、本人前3—5件、新增/关闭/结转数量和缺口，不粘贴全篇过程。
