# 文档写作与飞书交付

[输入确认与完整流程](references/workflow.md) · [团队使用说明](references/team-setup.md)

把一个具体问题讲到读者能理解、判断和使用。以准确的事实、必要的解释和展开充分的例子构成文章；文风修改服务于这个结果。

## 任务怎么接

- 独立写文章或改文风时，以本Skill为主。职业规划、面试、复盘等已有业务入口时，业务Skill负责来源、必需内容与交付位置，本Skill负责成文和编辑，两者要求一起满足。
- 先复用当前任务的读者、用途、来源、参考文章和交付面。能自行查清的先读；必需来源或写入目标有实质歧义时，只暂停依赖它的部分。
- 分清用户要**审阅、只排版、局部润色、重写、从零写作**中的哪一种。“像参考这样写”允许学习组织和讲解方式，不允许改动参考原件。只排版时保留正文事实与措辞；局部修改保留范围外内容和有效图表。
- 学生材料的既有业务交付规则继续适用。普通文章、只读审稿与聊天改写不因本Skill自动获得飞书写入、权限变更或公开发布授权。

## 写之前：确定文章要带读者走到哪里

内部用一句话说明读者读完要弄懂什么或能做什么，再安排章节。收集本次必需事实、案例和限制，区别事实、解释、假设与建议；内部分类不直接铺进正文。

有参考文章时，完整读本次指定的参考，抓住开头提出的问题、章节推进、例子展开和图文位置。参考已完整读过且没有新版本证据时，沿用观察，不为每次写作重复拉取全部材料。具体方法读 [成文与编辑](references/editorial-method.md)。参考的公司说法、指标和招聘流程需要另行核验；参考文风不等于承认它的事实正确。

长文开头给出当前读者最需要的判断或问题，接一小段导读、目录或总览。解释文从必要概念进入，案例文从情境进入，操作文从要完成的事进入。由内容决定顺序，避免给所有文章套同一副章节骨架。

## 写正文：把原因和例子展开

每段承担一个明确作用，可以是提出判断、交代原因、补充证据、推演例子、转折或安排动作。相邻段落通过同一个问题继续往下讲；标题、冒号和“首先其次”不能替代推理。

教学材料中的核心案例要让读者看见：遇到了什么、有哪些已知条件、为什么这样判断、可以怎样表达或操作、条件变化后怎样调整。按案例需要组织，不把这些词逐段写成固定标签。示例见 [改写示例与保留边界](references/before-after.md)。

事实不足时，保留原有概括或准确指出缺口。教学模拟可以补充推演，但要在相关位置一次说明模拟范围；不能把假设、行业常识、团队结果或待完成计划写成本人经历。术语、条件、否定、时间、归因与不确定程度保持准确。

## 编辑：先改文章，再改句子

1. **看主线。** 每节是否回答开头提出的问题，前文是否已提供理解后文的条件。合并跨章节重复，把解释移到读者第一次需要它的位置。
2. **看讲解。** 抽象建议后面有没有必要的原因、例子或动作。缺内容就补有依据的解释，保留岗位日常、公司待遇口径、案例推演和行动条件；精简不等于删成速查提纲。
3. **看段落。** 删除重复结论和空泛铺垫，把无主语、无具体对象的大词句改成连贯的判断与解释。长短句随意思变化，不刻意制造碎片、金句、反问或口语感。
4. **对照来源。** 逐项核对数字、条件、范围、比较对象、责任人、完成状态、归因、引文和链接。已有好段落可以保留；必要限制不因“去AI味”消失。

“赋能、闭环、不是……而是……”等只是检查线索，不能按词命中判坏。真实反驳、技术含义、独立并列项和有作用的连接词可以保留。不要用词频、字数或自评分证明文章自然。

## 选择形式与交付

原因用段落讲；同口径比较用表；操作用步骤；关系与分支用图。把连续解释塞进表格，或把正文缩写塞进框图，都需要重新组织。标题、加粗和色彩只承担定位作用，保持可预期的阅读层级。

长文成稿后主动补一层便于扫读的强调，让读者快速找到判断和条件；克制不等于正文完全没有重点。

- **加粗关键判断与动作。** 选择读者最需要记住的结论、取舍依据或下一步，标记能独立表达意思的短语，不整段加粗，也不把每段首句机械标粗。
- **高亮会改变做法的条件。** 截止时间、硬性限制、判断分支或关键数字需要读者特别留意时，默认用浅黄色背景；同文统一颜色。普通数字、术语和已有加粗不再逐项高亮。
- **保留判断的完整意思。** 强调范围包含必要的否定、可能性与适用条件，不能突出结果却让限定语被忽略。不设每段或每页的强调配额，短文按需要处理。
- 用户明确要求纯文字或保持现有格式时，按其要求交付。

飞书任务读 [飞书正文与写后审稿](references/feishu-delivery.md)，优先使用已配置的`lark-cli`。复杂文档配合`visual-document-delivery`；文档与讲解图实际应用`impeccable`的Read模式，飞书讲解图默认原生画板并紧邻相关正文。其他格式使用适合该格式的排版与图，按对应文档工具验收。

写入后从真实交付面重读正文、标题、表格和图注，修正重复、内部标签与模板拼接，再检查阅读效果。结构回读与视觉验收分别记录，不能互相替代。工具受限时准确说明未检查部分。

默认交付成稿或实际文件/链接。只有用户要求诊断或说明时才解释问题；编辑记录、自评分和写作过程留在正文外。诊断至少给一处有位置的原句或段落及针对性改法。已有外部文档未获修改授权时，只读并在聊天或本地给示例。
