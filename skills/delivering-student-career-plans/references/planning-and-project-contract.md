# 方向、公司、项目与投递合同

## 方向选择合同

学生正文默认只展开 1—3 个可以投的方向。每个方向至少回答：

| 字段 | 要回答的问题 |
|---|---|
| 优先级 | 主攻、并行补充、条件性拓展或选择性冲刺？ |
| 日常工作 | 一天主要处理什么输入、完成什么任务、交付什么结果？ |
| 为什么适合 | 当前哪段经历或能力能迁移，证据强弱如何？ |
| 可以投什么 | 使用哪些真实岗位名称检索？ |
| 关键补强 | 缺什么可观察证据，补到什么程度才可投？ |
| 薪资参考 | 目标城市、税前年包/月薪、样本日期与样本性质是什么？ |

方向分析先于学习计划：结合能力证据、偏好排序和现实门槛给出当前推荐及切换条件。用户明确要求比较时，要解释影响选择的利弊与代价，不能把比较压成一句“都可以”，也不能把主判断整体交给未来试做。一般排除理由留在内部；容易误选或确实影响决策的边界在正文说明。

产品、商业分析、开发是不同职业。若同一章节同时推荐两种职业，两者分别保留具体岗位、门槛和薪酬依据；不能只用产品岗薪资代表商业分析，也不能用研发薪资代表GTM。

## 行业与公司合同

行业/组织类型与岗位方向分开写。互联网、金融、外企、快消、央国企、研究机构不是六个独立职业方向；同一行业可同时存在 Agent 开发、模型评测和数据科学岗位。

每个方向建立公司池：

1. **第一批重点研究与投递**：岗位内容和学生证据最接近；
2. **补充公司池**：需要补一项关键证据或城市/组织条件略弱；
3. **选择性冲刺/长期关注**：岗位门槛更高或当前仅有历史样本。

公司池必须列真实公司名称，不能只写“中小厂/大厂/垂直公司”。动态信息分为：

- 当前或近期核验到的岗位样本：记录公司、岗位、城市、访问日、状态和来源；
- 长期研究池：只证明该公司值得持续检索，不暗示当前开放岗位。

AI Agent 方向存在时，额外检查：

- 是否单列大厂 Agent 池和中小型 AI/垂直场景公司池；
- 大厂中哪些是 Agent 应用开发、平台工程、RAG、评测，哪些偏基础模型、后训练、强化学习；
- 学生主投的是哪一类，哪些只做冲刺；
- 不能把“缺顶会论文”扩大成“大厂全部不能投”，也不能弱化核心算法岗的真实门槛。

## 岗位—公司—薪资待遇对照（核心正文）

每条保留路线至少展开一条具体公司岗位样本；用户指定更多公司、岗位或城市覆盖时按指定范围完成。公司池负责广度，逐条对照负责让学生判断真实选择，二者不能互相替代。可用紧凑表格或岗位小节，不强塞成一张超宽表。

| 必填内容 | 学生应得到的信息 |
|---|---|
| 具体岗位与公司 | 公司全称或明确品牌、真实职位名称；不能只写“产品／开发／大厂” |
| 城市与招聘阶段 | 实习／校招／社招、届别或经验要求；当下可申请还是未来岗位画像 |
| 状态与入口 | 当前样本／历史样本／仅研究池；真实来源链接、核验日期；开放状态未核实就明确写未确认 |
| 固定薪资 | 月薪／日薪／年薪、币种、税前税后、薪数；未知项明确未披露 |
| 浮动与补贴 | 奖金、提成、股票、签字费、外派／生活补贴及保证性；只保留有来源的信息 |
| 福利与工作安排 | 影响该学生选择的福利、办公／实习要求、工时或出差外派；来源没有披露就如实标明，共同未知项可集中说明，不套公司常识 |
| 匹配与差距 | 当前经历支持什么，哪条硬门槛或项目证据尚缺，补到什么程度适合申请 |

薪酬先在核心方向总览给出，再在具体公司岗位处展开构成。学生个人目标单独写，不能作为市场参考。只写“20—30万目标”“薪资有竞争力”或如何比较Offer的通用说明，不算已提供该岗位待遇。

**证据取用顺序：**目标公司具体岗位披露 → 同公司同类岗位资料 → 同城、同职业、同招聘阶段的可靠可比样本。记录日期和样本性质，说明可比依据。相邻届次、历史样本或可比公司不能冒充该公司当前报价；实习日薪不能外推为转正年包；社招／经理薪资不能直接套给应届生。

同时规划在校实习与毕业全职时，两种阶段分别给出薪资口径；只有实习日薪，不能声称毕业全职薪资研究已完成。若任务仅限实习规划，则按实习口径完成，不额外扩展全职研究。

**未披露的处理：**先保留真实岗位及其未公开项，继续寻找可比薪酬证据。找不到时可以交付已查明部分，但明确该方向薪资研究仍未完成；不能用“未披露”把整条方向的薪资研究算作通过，也不能编造数字或福利。其他字段已核验可继续完成，不因此停止全部规划。

**计算与外派：**固定月薪×保证薪数、浮动奖金、提成和外派补贴分别列出；“最高可达”不等于常见或保底收入。海外销售／外派机会进一步核对国内底薪、区域、外派周期、提成与补贴口径。只解释影响当前选择的差异，不写薪酬百科。

## 项目与执行顺序

默认顺序：

`方向与岗位 → JD 与现有证据 → 能力缺口 → 补强方案 → 简历版本 → 对口投递 → 面试复盘`

正文先解释补强、再讲简历与投递；执行顺序按证据准备度分支：已有经历足以支撑核心要求的岗位可以先投并继续补强，依赖新项目证据的岗位等项目达到简历进入条件再投。不要求用户另行授权这种准备工作的并行，也不为流程阻塞已有证据支撑的申请。实际代投或提交仍需对应授权。

项目数量服从明确范围。没有明确数量时，应届生通常 1—2 个；社招默认深挖既有项目/实习，不新增无法解释的训练项目。

先判断缺的是技术、产品决策、数据分析还是客户协作证据，再决定产出。技术项目、需求/原型验证、分析报告或客户方案按岗位选择；不能把技术工具作为所有职业的通用补强。反向核对项目交付物与本页具体岗位样本的核心职责，无法对应时调整项目或岗位样本。

每个项目必须回答：

- 对应哪个岗位和哪条缺口；
- 解决什么场景问题，数据和权限边界是什么；
- 学生本人完成哪些模块；
- 形成哪些代码、报告、Demo、评测或作品集；
- 最低可演示状态和最终验收分别是什么；
- 达到什么条件才进入哪一版简历；
- 支持哪些面试追问和失败案例复盘。

计划中、进行中和已完成必须分开。没有可检查产出前不生成成果型 bullet；团队方案、导师示例和目标指标不成为学生结果。
