# 公开 Skill 同步约定

本仓库集中维护校招交付团队可复用的业务Skill。作者的个人运行版和公开团队版可能有合理差异：公开版不带作者账号和实际业务路由，并包含团队接入说明。更新不能用整目录覆盖抹掉这些差异。

## 自动同步范围

只读取私有白名单明确列出的Skill源。原始简历、聊天、逐字稿、会议媒体、客户材料、业务数据、密钥、登录配置、生成缓存和未登记第三方目录不进入公开仓库。新增Skill先核对来源、业务范围和依赖，再加入白名单。

脚本 sync_public.py 使用上次已验收的本地源快照作为共同基线，对比本轮源改动与当前公开版。普通互不冲突的变更保留两边；同段冲突、源路径失效、文件移除、二进制变化或新隐私模式进入异常清单。自动流程不删除公共资源，不强推，不用失败刷新当作无变化。

白名单与精确脱敏映射、源快照及同步日志保存在作者本机私有目录。capture保存的是下一轮比较基线，只能在对应公开发布读回成功后更新，不能用提前capture掩盖尚未发布的源变更。

## 每轮发布

1. 核对公开工作树与远端状态，先保留已有人工改动；读取源白名单与上次日志。
2. 预览本地源变更。没有变化保持安静；有冲突保留双方并指出具体对象。
3. 对可合并变更应用精确脱敏，更新团队说明和文件清单。新规则若涉及入口/依赖变化，同时更新配置说明与测试。
4. 运行全量仓库/领域测试、Markdown引用和敏感信息检查。失败就保留待处理结果，不推送。
5. 仅提交本轮验证的规则/脚本/引用与清单。推送成功后核对远端提交、新鲜克隆和文件哈希，再保存源基线。应用计划会保存源文件指纹；若发布期间源又有新改动，capture必须拒绝推进旧基线，避免把未发布变化标为已同步。

公开副本自己的改动也属于同步范围。后台不能把其他聊天未提交的半成品当成已审核发布版本；发现这类状态应具体报告，用户明确要求当前批次发布的除外。

## 手动命令

以下源映射文件与状态目录均为私有路径，由部署者提供：

```bash
python3 scripts/sync_public.py plan --config "<私有源映射.json>" --state "<私有基线目录>"
# 在已授权的同步范围内，预览无冲突后加 --apply
python3 scripts/build_team_docs.py
python3 scripts/build_manifest.py
uv run --with pyyaml --with python-docx --with pdfplumber --with lxml   --with pypdf --with reportlab python scripts/verify_release.py
# 提交推送并独立核对远端后，才执行capture
python3 scripts/sync_public.py capture --config "<私有源映射.json>" --state "<私有基线目录>"
```

触发同步不授权写学生飞书、改权限、提交招聘申请、发布小红书或向团队发送消息。公开版本测试通过也不证明业务目标已完成。
